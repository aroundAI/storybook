## KB-215 — The Publish screen's title, description and tags could not be saved, and were lost on reload

> **Fixed (2026-10-24), #696.** Publish Settings has a **Save** button,
> enabled when a field differs from what is stored, with an "Unsaved
> changes" note beside it; a blank title disables it and says a title is
> required. Save calls `savePublishDetailsAction`
> (`packages/features/episodes/src/lib/server/mutations/publish-actions.ts`),
> which writes through `saveEpisodePublishDetails`
> (`packages/features/episodes/src/server/episode.service.ts`): the title
> and description rename the episode (owner, 2026-10-24: the episode list
> and header change too), and the tags are merged into `metadata.tags`
> without touching its other keys. The version is read on the server, not
> sent by the screen, because a Shorts-group save beside it moves the
> version without refreshing the page; a write that lands between the read
> and the update is re-read and retried, three times at most. The save is
> audit-logged like any episode update. Publish and Schedule still send
> whatever the fields hold, saved or not. A description may be 5000
> characters, YouTube's limit, rather than the episode form's 2000.
> Posts already scheduled keep the title they were scheduled with.

**Severity:** Medium — the owner, on every episode they retitle for
publishing. **Found:** the owner changing the title an episode publishes
with, 2026-10-24.

The Title, Description and Tags fields on the Publish screen were local
state in `publish-screen.tsx`, seeded from `episodes.title` and
`episodes.description`; Tags always started empty. Nothing wrote them
anywhere. An edit reached a publish only when Publish or Schedule was
pressed in the same visit (`buildReleaseConfigs` copies them into each
publish row); a reload or a visit to another stage put the episode's
values back and dropped the tags.

Reproduced on the local stack: edit the title, reload, and the old title
returns.

**Acceptance**
- [x] Save stores the title and description on the episode and the tags in
  `metadata.tags`, keeping other metadata keys —
  `packages/features/episodes/__tests__/kb215-publish-details.test.ts`
- [x] A write that moves the version between the read and the update does
  not fail the save, and repeated moves stop rather than loop — same file
- [x] After Save and a reload the fields show the saved values and the
  header shows the new title; a second save wins over the first; a blank
  title disables Save — `apps/e2e/tests/publishing/publish-details-save.spec.ts`
  (seen failing with the action stubbed to write nothing)
