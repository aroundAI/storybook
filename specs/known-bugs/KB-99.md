## KB-99 — Local, test and E2E run with personal accounts on, unlike production; account-owned data can still be created against a personal account

> **Fixed in part (2026-09-25), #PR1.** Every environment now runs with
> personal accounts off, as deployed, and a unit test binds the three places
> that say so. The E2E suite waits for where a signed-in person actually
> settles. Parity exposed KB-100 (profile settings unreachable in production),
> fixed in the same PR, and changed where KB-19's unplaced connect failures
> land (below). **Still open:** the database guard (part 2), in its own PR.

**Severity:** Medium. Nothing a customer sees was wrong because of the
mismatch itself, but it hid KB-100 and made every personal-account defect look
real. **Found:** personal-owners, re-measuring KB-48's leads (2026-09-25).

**The product is team accounts only** (owner, 2026-09-25): someone working
alone is a team of one. Personal account rows remain as each person's identity,
billing-customer, notification and audit anchor.

### What was wrong

| Where | Personal accounts | Personal billing |
|---|---|---|
| `sst.config.ts:940` (every deploy) | `'false'` (default, baked into `next build`) | unset → code default |
| `apps/web/config/feature-flags.config.ts` (code default) | **`true`** | `false` |
| `apps/web/.env` (dev, `build:test`, CI E2E) | unset → **`true`** | **`true`** |

So local development, the test build and CI's E2E all ran a product that no
deployment runs. Two consequences, both reproduced:

1. **KB-48's leads were artefacts.** "Personal owners can't reach the studio"
   and "57 policies refuse personal owners" describe a product that does not
   exist in production. Re-measured on main (a throwaway Postgres with all 185
   migrations): 49 membership-only policies on 19 tables, of which 16 already
   carry an `account_id = auth.uid()` branch and 3 are team-only by nature;
   **30 policies on 8 tables** refuse a personal owner. That is correct under
   team-only, and nothing was changed.
2. **Parity exposed KB-100.** With the flag off, `(user)/layout.tsx` redirects
   every personal page, `/home/settings` included, and nothing linked anywhere
   else.

The KB-48 plan (`specs/plans/KB-48-71-edd.md:48`) says the owner "works
personal-first". The owner's decision above supersedes it.

### Part 2 (open): account-owned data on a personal account

Reproduced as a signed-in user, in a rolled-back transaction on main:

| Statement | Result |
|---|---|
| `insert into projects (account_id = <own personal account>)` | **ok, 1 row**. `projects_create` explicitly admits `is_personal_account = true` |
| `insert into platform_connections (account_id = <own personal account>)` | **ok, 1 row** |
| `insert into external_api_keys` / `social_posts` (same) | got past RLS; failed only on NOT NULL |

`createProject` passes `account_id` straight through, with no account-type
check. The approved fix: a `kit.require_team_account()` trigger on `projects`
and the 20 account-scoped workspace tables, with a catalogue test so a new
table has to decide; `projects_create` without its personal branch; a check in
both project-create actions. `notifications`, `audit_logs`, billing and the
avatar bucket keep personal rows, which are legitimate.

**Existing rows (owner's statement, 2026-09-25):** no production project or
row sits on a personal account. The migration changes no data either way, and
fails loudly rather than modify anything if one exists.

### Changed behaviour: KB-19's unplaced connect failures

A failed platform connect that no workspace could be chosen for used to land
on `/home`, which rendered the message. `/home` now only redirects and drops
the query. So, with the lead's approval (option A), it lands on:

- **no team:** `/home/teams/create`, which now renders the message and carries
  the user menu;
- **several teams, no hint:** `/home/settings` (profile), which renders it.
  Still no team is guessed.

Both of KB-19's promises hold: it never guesses the workspace, and it never
loses the message. `connectFailurePath` never returns `/home` (unit-tested).
