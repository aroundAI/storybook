## KB-183 — An MCP client cannot link a team's existing characters and locations to an episode, so its screenplay knows only the cast its story created

**Severity:** Medium — a team that drives an episode from Claude over MCP
with characters it already has. Its screenplay, shots and audio stages
refuse every line those characters speak and every shot set in those
locations, so the agent must declare them as new (duplicating them) or stop.
Nothing breaks on the web, where the episode header links them. **Found:**
FILM-1909, driving every stage over MCP against a seeded episode.

**What happens.** The episode context every stage after the story reads
(`buildEpisodeContext`, apps/web/lambda/llm-worker/utils/context-builder.ts)
takes an episode's characters from `episodes.metadata.character_ids` and its
locations from `location_ids`. The web writes those ids when a person links
an asset in the episode header (`linkAssetToEpisodeAction`,
packages/features/episodes/src/lib/server/mutations/asset-link-actions.ts),
and the story commit adds the ones it creates. No MCP tool writes them:
`create_episode` and `update_episode` set the creative direction only, and
`upsert_asset` creates the asset without linking it. The story commit's
upsert ignores an asset that already exists, so it does not link it either.

**Reproduced.** In the FILM-1909 contract test, with Maya Chen, Director
Williams and the Observation Deck created as project assets and the episode
created through `create_episode`, the story committed, then every scene of
the screenplay was refused: `unknown_character` for both speakers and
`unknown_location` for the deck. The episode's metadata held only the
story's own new character and location. Linking the three assets as the web
header does (metadata `character_ids`, `character_names`, `location_ids`,
`location_names`) made every stage pass; the contract test and the
Playwright spec link them that way, through the API, as the web does.

**Proposed fix.** A `link_asset` author tool (studio:write), or `characterIds`
and `locationIds` on `create_episode` and `update_episode`, writing the
metadata through the same function the header's action uses (moved into the
episode service so both call it), with the asset checked to be the
episode's project's.

**Acceptance criteria.**
- An MCP client links an existing character and location to an episode, and
  the next screenplay brief lists them and its check accepts them.
- The link is the web's: the episode header shows the linked assets.
- An asset of another project is refused.
