## KB-143 — TikTok posts are refused: the app never requests video.publish, and a missing scope is not treated as a scope error

> **Fixed (2026-10-01), #489.** `TIKTOK_OAUTH_CONFIG.scopes` now includes
> `video.publish` and `isAuthError` matches `scope_not_authorized`. The
> `it.fails` "TikTokAnalyticsProvider classifies scope_not_authorized as a scope
> error" is a normal `it` now and passes; the old line-110 test was rewritten to
> "the app requests video.publish", with a second test that a connection
> lacking it is refused `scope_not_authorized`. Removing the scope turns 4
> tests red, the classifier 2.
>
> **Not done.** Existing TikTok connections lack `video.publish`, so their
> posts are still refused until the person reconnects, and `video.publish`
> needs TikTok's approval of the developer app (owner action). A reconnect
> prompt for a missing publish scope was **not** built: the missing-scope
> mechanism (`analytics-scopes.ts`) is analytics-only, and adding a publish
> scope there would mislabel it as "analytics not authorised".

**Severity:** High. The publish worker's TikTok post (`uploadToTikTok`,
`apps/web/lambda/publish-worker/handlers/tiktok.ts:14`) calls
`/v2/post/publish/video/init/`, TikTok's direct post, which needs the
`video.publish` scope. `TIKTOK_OAUTH_CONFIG.scopes`
(`packages/features/publishing/src/oauth/tiktok/config.ts:12-18`) asks only for
`user.info.basic`, `video.upload`, `video.list` and `user.info.stats`, so every
TikTok publish through the worker is refused for every connected user, and a
reconnect does not help. **Found:** 2026-09-30, building the TikTok sandbox
journey (FILM-1802).

Two defects in one path:

1. `video.publish` is never requested, so direct posting fails with
   `scope_not_authorized`.
2. `isAuthError` in
   `packages/features/content-analytics/src/providers/tiktok/tiktok-analytics.ts:72`
   matches `access_token_invalid`, `invalid_token`, `unauthorized`,
   `forbidden` and `access denied`, but not `scope_not_authorized`, TikTok's
   actual code. A connection missing a scope surfaces as a raw error instead of
   `TikTokAnalyticsScopeError`, which the sync uses to tell the user to
   reconnect.

### Reproduced (2026-09-30)

- `apps/vendor-sandbox/__tests__/tiktok-journey.test.ts:110`: with the app's
  own scopes, `uploadToTikTok` rejects with `/scope_not_authorized/`. It is a
  normal test asserting today's behaviour: when `video.publish` is added to
  `TIKTOK_OAUTH_CONFIG.scopes` and the test is rewritten to publish, this one
  goes away (the next test, which connects with `video.publish` requested,
  shows the post then works).
- `tiktok-journey.test.ts:255`, the `it.fails` "TikTokAnalyticsProvider
  classifies scope_not_authorized as a scope error", expects
  `TikTokAnalyticsScopeError` for a token without `video.list`; it fails
  today, so `it.fails` passes.

```
pnpm --filter vendor-sandbox exec vitest run __tests__/linkedin-journey.test.ts __tests__/tiktok-journey.test.ts
 ✓ __tests__/tiktok-journey.test.ts (10 tests)
 Test Files  2 passed (2)   Tests  21 passed (21)
```

### Proposed fix

Add `video.publish` to `TIKTOK_OAUTH_CONFIG.scopes` (this also needs the
scope approved on the TikTok developer app, and existing connections must
reconnect), and add `scope_not_authorized` to `isAuthError`. Note that
unaudited TikTok clients can only post privately; that is a separate limit.

### Acceptance criteria

- [ ] `TIKTOK_OAUTH_CONFIG.scopes` includes `video.publish`
- [ ] `isAuthError` matches `scope_not_authorized`
- [ ] In `tiktok-journey.test.ts` the `it.fails` "TikTokAnalyticsProvider
      classifies scope_not_authorized as a scope error" is changed to `it`
      and passes; the test at line 110 is rewritten to a publish that succeeds
