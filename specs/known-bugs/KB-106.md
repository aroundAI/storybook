## KB-106 — Eight prompts can never reach the LLM: the loader cannot render their files

**Severity:** Medium. Each of these features fails on every call, in every
environment, whatever the model would have returned. The worst case is quiet:
inline canon validation on the story page catches the error and falls back to
a "basic" extraction (`server/canon-actions.ts:1210`), so the page never shows
that the LLM extraction has not run once. The news services (anchor, producer,
entity extraction, topic summary) and the documentary roles fail outright.
**Found:** FILM-1803, while building the AI sandbox's every-prompt test,
2026-09-25.

`loadAndRenderPrompt` (`packages/features/prompt-engine/src/lib/server/prompt-loader.ts`)
reads `template.system_prompts` and sorts it. Eight prompt files instead carry
a bare `system_prompt` string, the older format, so the loader throws
before any LLM call. `movie/act-context-extraction` also has no `variables`,
so it fails one step earlier:

| Registry key | Error |
|---|---|
| `canon-extraction` | `Cannot read properties of undefined (reading 'sort')` |
| `documentary/fact-checker-role` | same |
| `documentary/researcher-role` | same |
| `news-generation/anchor-role` | same |
| `news-generation/entity-extraction` | same |
| `news-generation/producer-role` | same |
| `news-generation/topic-summary` | same |
| `movie/act-context-extraction` | `Cannot convert undefined or null to object` |

**Reproduced** by rendering every registered prompt through the real loader
(each of the eight threw as above; the other 19 rendered), and then through
the real `executeLLM` against the AI sandbox
(`apps/vendor-sandbox/__tests__/every-prompt.test.ts`, which lists the eight
in `KNOWN_BROKEN` with this id and error).

**Why nothing caught it.** `prompt-format.test.ts` accepts `system_prompt` as
one of "two formats" when checking prompt text. The test describes an
assumption; the loader implements one format. The llm-worker's own renderer
(`apps/web/lambda/llm-worker/llm-utils.ts`) does handle both, but no caller of
these eight goes through it: the Lambda's automatic canon commit
(`utils/commit-story-canon.ts`) calls the package `executeLLM` as well.

**Related, read only (a lead):** `lib/documentary/fact-checker.ts`,
`lib/documentary/researcher.ts` and `lib/canon/act-context-bridge.ts` call
`fact-checker-role`, `researcher-role` and `act-context-extraction`, slugs the
registry does not hold (it has `documentary/…` and `movie/…`), so those three
call sites fail with "Prompt template not found" even once the files render.

### Acceptance criteria

- [ ] The eight files use `system_prompts[]`, and `act-context-extraction` has
  `variables`
- [ ] `prompt-format.test.ts` runs the real loader over every prompt, so the
  format test cannot drift from the loader again. Seen red on `main`
- [ ] The three unregistered slugs point at the registered keys
- [ ] The eight leave the sandbox's `KNOWN_BROKEN` list: `executeLLM` renders
  them against the sandbox (four then meet KB-107)
