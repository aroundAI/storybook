## KB-107 — Four wrapper_key prompts can never be read: the executor wants an array, the callers an object

> **Fixed (2026-09-25), #369.** One shape now holds from prompt to caller: the
> four prompts drop `wrapper_key` and their `schema_for_llm` asks for the
> wrapper the callers already read (`{ extraction: … }`, `{ fact_check: … }`,
> `{ research: … }`, `{ bridge: … }`; act-context had no schema and gains one).
> `executeLLM` then returns the object whole. No caller changed. This is the
> smaller of the two consistent fixes: the other, reading `result.data` bare,
> touched eight call sites and every test that mocks them. A format guard now
> allows a `wrapper_key` only where the prompt's Zod schema makes that key an
> array (red on the four before the fix). Proved by a real `executeLLM` round
> trip against the AI sandbox for all four (red before: `Value for key "…" is
> not an array`).

**Severity:** Medium. No output a model could produce satisfies both the
executor and the caller, so each of these fails on every call once KB-106
is fixed. Canon validation falls back quietly; the documentary roles and the
act-context bridge fail. **Found:** FILM-1803, 2026-09-25, as the next failure
behind KB-106.

Four prompts set `output.wrapper_key`: `canon-extraction` (`extraction`),
`documentary/fact-checker-role` (`fact_check`), `documentary/researcher-role`
(`research`) and `movie/act-context-extraction` (`bridge`).

- `executeLLM` (`llm-executor.ts`, step 10) replaces the result with
  `result[wrapper_key]` and throws `Value for key "<key>" is not an array`
  unless that value is an array.
- Every caller then reads the key again, as an object:
  `result.data.extraction.immutableEvents` (`server/canon-actions.ts`),
  `result.data.fact_check.overall_verdict`, `result.data.research.claims`,
  `result.data.bridge.characterStates`.

A model that follows the prompt (`{ "extraction": { … } }`) is rejected by the
executor. One that returns an array under the key passes the executor, but
then the caller reads `.extraction` on an array and gets `undefined`.

**Reproduced** against the AI sandbox with KB-106's rendering failure patched
out: the sandbox answered `canon-extraction` with the object the caller reads,
and `executeLLM` threw `Value for key "extraction" is not an array`
(`apps/vendor-sandbox/__tests__/every-prompt.test.ts`, and the mutation guard
"KNOWN_BROKEN stays quiet when KB-106 is fixed" in
`tooling/mutation-guards/film-1803.json`).

The Lambda's automatic canon commit (`apps/web/lambda/llm-worker/utils/commit-story-canon.ts`)
calls the package `executeLLM` too, so it meets the same error.
