## KB-187 — Extracting an asset description from the story sidebar returns nothing: the action opens its run on the user's personal account

**Severity:** Medium — "Create in library" opens with an empty description for every user, with no error shown. **Found:** running `ai-sandbox-evidence.spec.ts` on main b05c463fc for FILM-1901's open e2e item.

**What happens.** `extractDescriptionAction` (`packages/features/episodes/src/lib/server/mutations/asset-link-actions.ts:112`) passes `user.id` as the `accountId` of the run it opens through `describeAsset`. Generation runs belong to a team account, so the run store refuses it: `opening a asset_description run: refused: generation runs belong to a team account (a solo user is a team of one); <user id> is a personal account`. The action's catch returns `success: true` with `description: ''`, so the dialog opens blank and nothing says why.

**Reproduced.** Run with the app under the egress guard (`EGRESS_GUARD_LOG`) so the other two specs pass: the key-check spec and the sandbox-status spec pass, and `ai-sandbox-evidence.spec.ts:333` fails (`getByPlaceholder('Describe this character...')` stays `""` for 60 s). The app log shows the RunError at `store.ts:127` called from `asset-link-actions.ts:122`.

**Proposed fix.** Open the run on the episode's team account, resolved from the episode or project the sidebar belongs to, and return a refusal as a value rather than an empty description. Check for the same shape elsewhere: `git grep "accountId: user.id"` over the actions that open a run.

**Acceptance criteria.**
- [ ] The sidebar's "Create in library" shows the sandbox's description.
- [ ] A run that is refused shows an error instead of an empty description.
- [ ] `ai-sandbox-evidence.spec.ts` passes.
