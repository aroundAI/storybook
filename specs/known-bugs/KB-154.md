## KB-154 — AI Insights is sent a literal 0 for project watch time and subscribers

**Severity:** Medium. A language model is told the project's watch time and
subscribers gained are zero when nobody measured them, and its reading can
repeat that as a finding ("no watch time this period"). Nothing is written
or lost, and the figures it is given beside them are real, which is why it
is not High. **Found:** 2026-10-01, building FILM-1705, which stopped the
MetricCards drawing the same zeros.

`components/analytics-dashboard.tsx` builds `totals` from
`getProjectAnalyticsAction` with `watchTimeSeconds: 0` and
`subscribersGained: 0` — commented "Not available at project level". FILM-1705
§5 calls that a coverage statement rendered as a measurement, and the
MetricCards now read a copy with both set to `null` and say "Not totalled
here". But the same `totals` object is `aggregateAnalytics.totals`, which
`AIInsights` sends to `generateInsightsAction`; the `analytics-insights` job
(`apps/web/lambda/llm-worker/handlers/analytics-insights.ts`, "Prepare
analytics summary for LLM") passes `totals` to the model as is, and
`calculateChanges` works a period-over-period change from it.

The payload schemas (`AnalyticsTotalsSchema` in `server/insights-actions.ts`,
the `analytics-insights` payload in `prompt-engine/src/lib/llm-job-payloads.ts`)
require both as numbers, so `null` cannot be sent without changing them.

### Fix

Make both fields nullable in the two schemas, send `null` from the dashboard
(the MetricCards' copy already is), and have the job omit a null figure from
the summary rather than state it. A unit test on the handler's summary: a
null watch time does not appear as `0`.

### Acceptance

- [ ] The insights payload carries `null`, not `0`, for a total the project
  does not measure, and the summary the model reads leaves it out.
