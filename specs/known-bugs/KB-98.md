## KB-98 — `publish_tags` accepts a tag from any account

> **Fixed (2026-09-25), #387.** `publish_tags_create` now requires the tag to
> belong to the video's account (`tag_in_account`), and a tag's `account_id`
> can no longer be changed by a signed-in user. The migration
> (`20260925120329_kb98-account-scoped-references.sql`) deletes links that
> already cross accounts and lists their publish ids in a NOTICE; the next
> full dim-sync rewrites their `video_dim.tags`. Measured on the local stack:
> a seeded cross-account link put `topic:kb98-t6-foreign` in the other
> account's `video_dim.tags`; after the migration, dim-sync wrote only the
> own tag. `setPublishTagsAction` and `bulkTagPublishesAction` also check
> scope before clearing a video's tags, and return the refusal as a value.
>
> The class sweep ("a row names another account's object and nothing checks
> it") found the same gap for channels. Reproduced on `publishes` (insert
> and update), both publishing-config tables, `short_publications` and
> `social_posts`. The same migration fixes them: that is the database side
> of KB-109. It also found `manual_tasks` and
> `analytics_experiments.project_id`, filed as KB-113. Production
> ClickHouse is off, so it holds no leaked slugs.
> `publish-tags-account-rls.test.sql` and
> `connection-account-scope-rls.test.sql` were red on main (4 of 8 and 9 of
> 17) before the fix; 15 mutation guards are in `kb-98.json`.

**Severity:** Low. It needs the other account's tag id (a UUID), and the
foreign tag lands on the caller's own video. **Found:** KB-93's class sweep,
2026-09-24.

`publish_tags_create` (`20260827102452_content-taxonomy.sql:77`) checks that
the caller can reach the *publish*, and never looks at the tag. A foreign key
does not run RLS, so any tag id is accepted, including one from an account the
caller does not belong to.

**Reproduced** on the local database in a rolled-back transaction, acting as
`authenticated` through RLS for a user who is **not** a member of the tag's
account: `insert into publish_tags` on the user's own publish with the other
account's tag succeeded (`foreign-account tag on own publish | 1`).

**Why it matters beyond the row:** `dim-sync.ts:213` reads `publish_tags`
with the admin client and writes each tag's `dimension:slug` into the
caller's `video_dim.tags` in ClickHouse, which has no RLS. So another
account's tag slug would be copied into this account's analytics, and
grouped by in tag medians.

**Proposed fix:** the same shape as KB-93 — the insert policy joins
`content_tags` and requires `t.account_id` to equal the publish's project
account; a pgTAP test for a user in both accounts and for an outsider.
