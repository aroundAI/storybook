## KB-138 — A database error is shown as "not found"

> **Fixed (2026-09-28), #454.** `requireRow()` (`@kit/next/refusals`) refuses
> "not found" only when `.single()` found no row (`PGRST116`, or no error and
> no data), and throws any other error as a crash, which is logged. All 26
> actions that refused a failed read as "not found" use it: the 17 counted
> below, and 9 more that logged the error first and were missed by the
> one-line count. `kb138-errors-not-not-found.test.ts` fails on the old shape
> (26 on main, 0 after). A mock that modelled "not found" as an error with no
> code now uses PostgREST's real `PGRST116`.
>
> **The rest (2026-09-29), #475.** The sites of the same `if (error || !row)`
> shape that threw a plain `Error` or returned "not found" as a value are
> fixed too: this wording is what sent the "Social post not found" lead
> after a missing row while KB-137's timeout was the cause. The rule lives
> once, in `@kit/shared/rows` (`readFailed`, `whyNoRow`), which `requireRow`
> now uses. 28 throwing sites word their message with `whyNoRow`; the 9 that
> return "not found" to a user throw first when the read failed. The scan
> test covers thrown and returned messages; guards in `kb-138.json`.

**Severity:** Low. The message is wrong rather than the outcome, but it sends
whoever reads it after the wrong cause, and a refusal never reaches
monitoring. **Found:** 2026-09-28, with KB-137: a statement timeout (HTTP 500)
reached the page as "Social post not found".

### What happens

`if (error || !row) throw … 'not found'` treats every PostgREST error the same
as no row: a timeout, a dropped connection, a malformed filter. Counted on
main (`git grep -E -A1 'if \([A-Za-z]*[eE]rror \|\| ![A-Za-z]+\)'` over
`apps/web/app`, `apps/web/lambda` and `packages`, tests excluded): 247 sites
of that shape, 57 of them followed by a "not found" message, 17 of those as an
`ActionRefusal`. An `ActionRefusal` is returned to the page as a value
(KB-6), so a crash thrown that way is never logged as one.

### Proposed fix

Throw `error` as a crash when it is set, and refuse "not found" only when
there is no error and no row. Fix the 17 `ActionRefusal` sites first, then
the rest of the 57; a scan test in the style of
`kb105-unchecked-updates.test.ts` keeps new ones out.

### Acceptance criteria

- [x] No `ActionRefusal('… not found')` is raised for a PostgREST error
- [x] A scan test fails on a new `if (error || !row)` that reports "not found"
