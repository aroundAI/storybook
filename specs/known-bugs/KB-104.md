## KB-104 — A publish sends the platforms a thumbnail from any URL on an allowlisted storage domain, another tenant's or an attacker's

**Severity:** Medium — any writer who can publish chooses the image the
worker downloads and uploads to the channel: another tenant's thumbnail, or
content from a host the attacker controls. The worker fetches it from inside
the deployment. **Found:** KB-90 (2026-09-25), looking for the same shape as
the intro and thumbnail save actions.

`publishToAllAction` takes a `thumbnailUrl` per platform from the client
(`packages/features/publishing/src/lib/schemas/publish.schema.ts:53`,
`z.string().url()`), stores it on the publish row
(`packages/features/publishing/src/server/publish-actions.ts:256`) and passes
it to the upload after `validateContentUrl`
(`publish-actions.ts:351`, and `:643` for a scheduled publish). The YouTube
and Facebook handlers download it (`apps/web/lambda/publish-worker/handlers/youtube.ts:88`,
`facebook.ts:28`).

`validateContentUrl` (`packages/features/publishing/src/lib/url-validation.ts:74`)
checks only that the **host ends in** an allowlisted domain:
`r2.cloudflarestorage.com`, `supabase.co`, `cloudfront.net`,
`s3.amazonaws.com`. Anyone can create a host under each of those.

### Reproduced (2026-09-25, `main` ddc5568a)

The real function, `NODE_ENV=production`, in a throwaway vitest file in
`packages/features/publishing`:

| URL | `validateContentUrl` |
|---|---|
| `https://abcdefghijklmnop.supabase.co/storage/v1/object/public/project-assets/episodes/<another tenant's episode>/thumbnails/en-1.png` | **ALLOWED** |
| `https://attacker-owned-project.supabase.co/storage/v1/object/public/x/payload.png` | **ALLOWED** |
| `https://d1234abcdef.cloudfront.net/anything.png` | **ALLOWED** |
| `https://any-bucket.s3.amazonaws.com/anything.png` | **ALLOWED** |
| `https://attacker.example/x.png` (control) | blocked |

Not yet driven through a publish end to end (it needs a connected channel);
the path from the request to the download is by reading, cited above.

### Proposed fix

Validate `thumbnailUrl` as KB-90 validates the saved thumbnail: accept only
`ownedStorageKey(storage, 'project-assets', url, episodeThumbnailFolder(episodeId))`
— an upload this app issued, in the episode being published — and refuse
anything else as a value. `validateContentUrl`'s domain list then guards
only URLs the app did not issue itself, if any remain.

### Acceptance criteria

- [ ] A publish with another episode's, another tenant's or a foreign host's thumbnail is refused and writes no publish row (unit, red first)
- [ ] A publish with the episode's own uploaded thumbnail still goes through (E2E through the publish screen)
