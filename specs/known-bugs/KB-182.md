## KB-182 — Eighteen web Generate actions throw a run refusal instead of returning it, so production shows a generic sentence

**Severity:** Low. A team that turned server generation off, or a user
pressing Generate on a stage another run already holds, is refused
correctly, and no run is left behind. On these actions the refusal
reaches the page as production's generic "An error occurred…" sentence
instead of its words. **Found:** FILM-1910 (#581), while making web
Generate refuse when server mode is off.

### What happens

Since #581, `openRunForJob` (`packages/ai-gateway/src/jobs.ts`) opens every
web job's run in server mode. Before that, a team with server generation
off got an external run here, which the job trigger and `dispatch()`
refused with a 500, and the run held the stage for 30 minutes. That run
can no longer be created. `openRun` now refuses with a `RunError`
(`SERVER_GENERATION_DISABLED`, or `RUN_IN_PROGRESS` when the stage is
held), and `runRefusalMessage` words it for the page.

Five call sites show those words: `convertToScreenplay`,
`generateShotList`, `refineStory` and `refineScreenplay`, which use
`.catch(refuseRunError)` inside `returnRefusals`, and
`generateAudioCuesAction`, which returns the message in its result. The
other eighteen let the `RunError` propagate. A production build replaces
a thrown message with a generic sentence (KB-6), so the user does not
learn why.

Reproduced for `convertToScreenplay` before #581 wrapped it: with
`account_ai_settings` server off, the press showed no words. The E2E
case in `apps/e2e/tests/generation/dual-mode.spec.ts` goes red without
`refuseRunError`. The eighteen below were found by reading every
`openRunForJob` caller: none catches the `RunError`, and several are bare
`enhanceAction`s that cannot return a refusal at all.

### The eighteen call sites

- `apps/web/app/api/research/upload/route.ts:130` (a route handler: answer with the message and a 4xx)
- `packages/features/audio-generation/src/server/audio-cue-actions.ts:312` (`generateAudioForCue`)
- `packages/features/audio-generation/src/server/translate-dialogue-action.ts:102`
- `packages/features/content-analytics/src/server/insights-actions.ts:156`
- `packages/features/content-analytics/src/server/language-insights-actions.ts:128`
- `packages/features/episodes/src/lib/server/mutations/publish-actions.ts:222`
- `packages/features/episodes/src/lib/server/mutations/season-generation-actions.ts:90`
- `packages/features/episodes/src/server/actions.ts:302` (story queued by `createEpisodeWithContext`)
- `packages/features/episodes/src/server/batch-episode-actions.ts:82` and `:441`
- `packages/features/episodes/src/server/bulk-actions.ts:162`, `:272`, `:411`, `:538` and `:685`
- `packages/features/episodes/src/server/source-upload-actions.ts:261`
- `packages/features/episodes/src/server/story-actions.ts:93` and `:210`

### Proposed fix

Wrap each action in `returnRefusals` where it is not already (the KB-6
scan in `packages/next/__tests__/kb6-caught-action-message.test.ts` lists
the bare ones), and add `.catch(refuseRunError)` to its `openRunForJob`
call. A bulk action that collects per-episode failures records
`runRefusalMessage(error)` for the episode instead. The route handler
answers with the message.

### Acceptance criteria

- With server generation off, each of the eighteen shows the
  `SERVER_GENERATION_OFF_REFUSAL` words in a production build, and opens
  no run.
- A guard fails if an `openRunForJob` caller lets a `RunError` reach a
  server action's boundary unworded.
