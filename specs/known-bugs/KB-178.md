## KB-178 — A Reel-candidate scene's shot note is sent to a prompt that never reads it

**Severity:** Low — shots for the scenes the Reel Scout picks are written
without the hook it asks for; nothing fails and nothing is lost from the
database. **Found:** KB-177, whose stage check fails #561's shots stage on it.

The Shot Director (`packages/features/episodes/src/agent/skills/shot-director-skill.ts`)
builds a note for a Reel-candidate scene ("PRIORITY: This scene is a Reel
candidate. Lead with a high-impact visual hook in Shot 1. …") and sends it to
`scene-shot-generation` as `reel_note`. The template declares `reel_note`
(since #216) but no prompt text places `{{reel_note}}`, so the renderer
drops it. It is the only variable any template declares and never places.

prompt-engine's KB-126 scan passes the call, because it checks that a key is
declared, not that it is placed.

**Reproduced** by rendering `scene-shot-generation` with `renderTemplate` and
`reel_note: 'CANARY-REEL-NOTE'`: the canary is in neither the system prompt
nor the user prompt. #561's shots stage sends `reel_note: ''` for every
scene, which would keep the note lost once the stage replaces the skill.

**Proposed fix:** place `{{reel_note}}` in the template's user prompt, near
the scene content, and have the shots stage send the note the skill builds
for Reel candidates. Then extend the KB-126 scan to fail a template variable
that no prompt text places.

### Acceptance criteria

- [ ] A Reel-candidate scene's prompt contains the priority note; any other scene's prompt does not
- [ ] The shots stage sends the note, and KB-177's stage check passes on it
- [ ] A test fails any template variable that no prompt text places
