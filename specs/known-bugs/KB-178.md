## KB-178 — A Reel-candidate scene's shot note is sent to a prompt that never reads it

> **Fixed (2026-10-03), #570.** The owner decided the note must reach
> the model, so Reel candidates get reel-optimised shots (2026-10-03). This is
> an intentional prompt change:
>
> - `scene-shot-generation` (version 5) places `{{reel_note}}` after the
>   scene content and before the requirements. An unflagged scene sends `''`,
>   which leaves only a blank line and no heading.
> - The note's text lives once, in `reelNoteFor`
>   (`@kit/prompt-engine/schemas`). The Shot Director sends it in server
>   mode, as it did since #216.
> - The shots stage sends it too. `StageDefinition.prepare()` takes an
>   optional `earlier`, the parts the run has already accepted. `runStage`
>   passes them, and FILM-1908's MCP tools will pass `generation_run_parts`.
>   A scene part reads the reel_scout part from it, so a flagged scene's brief
>   carries the note in its variables, its instructions and `context.reelNote`.
> - `prompt-variables.test.ts` fails a variable a template declares and never
>   places. `reel_note` was the only one.
>
> Guards RN1–RN5 in `tooling/mutation-guards/kb-178.json` each go red.
> Placing the note without the stage change fails #561's stage on
> `unfilled {{reel_note}}`, so the two ship together.

**Severity:** Low — shots for the scenes the Reel Scout picks are written
without the hook it asks for; nothing fails and nothing is lost from the
database. **Found:** KB-177, whose stage check fails #561's shots stage on it.

The Shot Director (`packages/features/episodes/src/agent/skills/shot-director-skill.ts`)
builds a note for a Reel-candidate scene ("PRIORITY: This scene is a Reel
candidate. Lead with a high-impact visual hook in Shot 1. …") and sends it to
`scene-shot-generation` as `reel_note`. The template declares `reel_note`
(since #216) but no prompt text places `{{reel_note}}`, so the renderer
drops it. It is the only variable any template declares and never places.

prompt-engine's KB-126 scan passes the call, because it checks that a key is
declared, not that it is placed.

**Reproduced** by rendering `scene-shot-generation` with `renderTemplate` and
`reel_note: 'CANARY-REEL-NOTE'`: the canary is in neither the system prompt
nor the user prompt. #561's shots stage sends `reel_note: ''` for every
scene, which would keep the note lost once the stage replaces the skill.

**Proposed fix:** place `{{reel_note}}` in the template's user prompt, near
the scene content, and have the shots stage send the note the skill builds
for Reel candidates. Then extend the KB-126 scan to fail a template variable
that no prompt text places.

- [x] A Reel-candidate scene's prompt contains the priority note; any other scene's prompt does not (`prompt-engine/__tests__/scene-shot-reel-note.test.ts`; `generation/__tests__/stages-part-d.test.ts` "sends the Reel Scout's note for the scene it flagged")

- [x] A test fails any template variable that no prompt text places (`prompt-variables.test.ts` "every template places every variable it declares")
