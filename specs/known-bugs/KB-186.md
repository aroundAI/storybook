## KB-186 — Generate Story after ideation fails with an episode-modified error: the ideation commit bumps episodes.version under the open page

> **Fixed (2026-10-04), #607.** The page now sends the version the ideas
> were committed at. The ideation stage's commit returns `{ id, version }`
> (`packages/features/generation/src/stages/ideation.ts`), the worker's
> reply carries it (`handlers/story-ideation.ts`), and the ideation page
> sends `max(rendered, storedAt)` with Generate Story and refreshes the
> episode (`ideation/page.tsx`); bulk generate records it for its story
> phase (`bulk-generate/ideation-phase.tsx`), whose stale version had become
> the story run's target version and failed its commit with TARGET_CHANGED.
> The lock still refuses a version this user has not seen. On main the bug
> was a race: the page refreshes when any run on the episode closes
> (`useOpenExternalRuns`), and only a click before that refresh was refused,
> as in the run above. `apps/e2e/tests/sandbox/story-after-ideation.spec.ts`
> (ideation then Generate Story, twice) and the full
> `studio-flow-evidence.spec.ts` pass on the fix against the AI sandbox; on
> main the new spec stops at the story, where KB-188, found with this,
> refused the story's own commit.

**Severity:** High — every user who generates ideas and then clicks Generate Story on the same page is refused, so the studio flow cannot go past ideation without a reload. **Found:** running FILM-1804's `studio-flow-evidence.spec.ts` on main b05c463fc for FILM-1901's open e2e item.

**What happens.** The ideation worker handler now runs on the core, and the `ideation` stage's commit stores the ideas on `episodes.metadata` (`packages/features/generation/src/stages/ideation.ts`, op `update` on `episodes`; part B, #562). The old handler stored nothing. A trigger bumps `episodes.version` on every update, so the row is at version 2 when the ideas arrive over the WebSocket. The ideation page still holds the version it was rendered with (`ideation/page.tsx:111`, version 1), and `generateFullStoryAction` compares it with the row (`packages/features/episodes/src/server/story-actions.ts:192`) and throws `OptimisticLockError`. The POST answers 500 and the page stays on `/ideation`.

**Reproduced.** Seeded team, project and episode; ideation run through the local queue and the sandbox; Generate Story clicked. The spec failed at `studio-flow-evidence.spec.ts:213` (`expect(page).toHaveURL(/\/story$/)`, still `/ideation` after 120 s). The app log shows `OptimisticLockError` from `story-actions.ts:193`. Read afterwards, the episode row is at `version: 2` with `ideas_generated_at` set.

**Proposed fix.** The page must send the version the ideas were committed at: return it from the commit (`commit.data`) and the WebSocket result and use it in the click path, or refetch the episode after the ideas arrive. Add the second submission to the spec: ideate again, then Generate Story.

**Acceptance criteria.**
- [x] After ideas arrive, Generate Story on the same page reaches `/story`.
- [x] `studio-flow-evidence.spec.ts` passes end to end on the fixed tree.
