## KB-191 — The LLM WebSocket sends the user's access token in the URL query string

**Severity:** Medium — every signed-in user who has a studio page open sends
a live Supabase access token (a bearer credential, valid for its lifetime)
in a URL. Anything that records URLs records the token. **Found:** the
FILM-2015 packaged e2e, 2026-10-05: the publish page's console printed the
WebSocket connection URL.

**What happens.** `packages/ui/src/hooks/llm-websocket-provider.tsx:129`
opens the socket with ``new WebSocket(`${wsUrl}?token=${token}`)``. The
`$connect` handler (`apps/web/websocket/connect.ts`) reads it back from
`event.queryStringParameters?.token` when no `Authorization` header is
present, and already logs a `[Security] Query string authentication used`
warning for it. A browser `WebSocket` cannot set request headers, so the
browser client always takes the query-string path and the warning fires on
every connection.

Query strings are recorded in API Gateway access logs, Next dev server logs,
proxies and load balancers, and browser history. The token is therefore
readable by anyone with log access for as long as it stays valid.

**Fix sketch.** Either:

1. Pass the token as a WebSocket subprotocol:
   `new WebSocket(url, ['access_token', token])`. `$connect` reads
   `Sec-WebSocket-Protocol`, validates the token, and echoes the first
   protocol back in the 101 response. Headers are not logged by default.
2. Or issue a one-time, short-lived connection ticket from a server action
   and put only the ticket in the URL. A leaked ticket is useless after one
   use.

Then reject query-string tokens after a deprecation window, and stop logging
the connection URL in the client.

**Acceptance criteria.**
- The browser client no longer puts any credential in the URL.
- `$connect` accepts the new form and, after the window, refuses
  `?token=`; a unit test in `apps/web/websocket/__tests__/connect.test.ts`
  covers accepted, refused and echoed-protocol cases.
- A sandbox e2e against `apps/vendor-sandbox` (`ws://127.0.0.1:4121`) opens
  the socket and receives a job message with no token in the URL.
