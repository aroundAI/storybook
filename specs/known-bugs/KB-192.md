## KB-192 — With no metric rows, the analytics page shows Likes, Comments and Shares as 0 beside a Views card that says Not measured

> **Fixed (2026-10-05), #642.** Every count total (views, likes, comments,
> shares) now starts at null and adds through `addMeasured`
> (`@kit/clickhouse`), the rule views, revenue and X's shares already used,
> so a total over no rows is null and every card says Not measured. A
> measured 0 is still 0. `queryTotals` returns its no-rows totals whole
> when no row was read. The Overview tab's count cards now tell a failed
> read ("Could not be read.") from a total nothing measured ("Not
> measured."): `countClaim` takes `Measured<number | null>`. The project
> overview page's snapshot, which gave 0 views, likes and comments when
> nothing was published or ClickHouse failed, gives null too.

**Severity:** Low — every team on the analytics page before its first
sync, or with a date range or platform selection that has no rows. It
reads as "nobody liked or shared anything" where nothing was measured.
**Found:** checking the Views card's "Not measured" after #636 (KB-149,
KB-162, KB-167).

### What happened

Reproduced on local lane B (Supabase 5542x, ClickHouse 18123, web 3001):
a team with one YouTube publish and no `video_metrics` rows, at
`/home/<team>/studio/<project>/analytics`. Read from the DOM:

| Card | Shown |
|---|---|
| Views | Not measured |
| Likes | **0** |
| Comments | **0** |
| Shares | **0** |
| Watch Time, Subscribers, Revenue | Not measured |

On the Overview tab below, Total Likes, Comments and Shares read **0**, and
Total Views read **"Could not be read."**: a total nothing measured was
called a failed read.

### Why

- `getEpisodeAnalytics`, `getSeasonAnalytics` and `getProjectAnalytics`
  (`aggregation-queries.ts`) summed likes, comments and shares from
  `let total = 0` and `+=`, while views were summed from null with
  `addViews`. With no rows the loop never ran, so views stayed null and the
  rest stayed 0. The empty-scope returns wrote 0 for them too, and the
  platform-filtered empty season wrote 0 for views, saves and revenue as
  well.
- `MetricCards` read `data?.likes || 0` and `data?.comments || 0`, turning
  a null into 0 even had one arrived.
- `queryTotals` (`@kit/clickhouse`) and the company dashboard's empty
  totals gave likes and comments 0 over no rows.
- `countClaim` rendered every null as "Could not be read.".

### Acceptance criteria

- [x] With no rows, the Views, Likes, Comments and Shares cards each say
      Not measured — `unmeasured-totals.spec.ts`, "no rows", against lane B.
- [x] With a row, each card shows the figure the row measured — the same
      spec, "a row" (120 / 12 / 3 / 2), with ClickHouse read.
- [x] A measured 0 is still 0, and X's unmeasured shares stay null beside
      measured likes — `unmeasured-counts.test.ts`, for the episode, season
      and project totals; seen to fail on main's code first.
- [x] The Overview tab says "Not measured." for a total nothing measured
      and "Could not be read." only for a failed read — `card-claims.test.ts`.
- [x] No composite score is introduced; the engagement rate is unchanged
      (an unmeasured count adds nothing to its numerator, as before).

Experiment snapshots (`experiment-service.ts`) still sum counts from 0:
their totals are a stored, pinned format (`experiment-snapshot.test.ts`)
and are left as they are.
