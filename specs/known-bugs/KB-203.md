## KB-203 — Production analytics never ran: the deployed app was never given its ClickHouse settings

> **Fixed (2026-10-19), #682.** The `StorybookWeb` environment in
> `sst.config.ts` forwards the five `CLICKHOUSE_*` settings when they are
> set, in the same style as the MCP settings beside them. Test:
> `packages/shared/__tests__/web-env-forwarding.test.ts` requires each of
> them, plus `STORAGE_PROVIDER` and `R2_PUBLIC_URL`, in that block; 5 of its
> 8 cases are red on main.

**Severity:** High. No analytics in production: no figures on any
Analytics page, nothing for `get_project_analytics`, `get_daily_digest` or
the morning report, and the sync skipped writing.

**Found:** 2026-10-19 by the owner's reporting session: every analytics
view was blank, and StoryBook said its analytics database was disabled in
production.

**Cause:** `isClickHouseEnabled()` (`packages/clickhouse/src/client.ts`) is
`process.env.CLICKHOUSE_ENABLED === 'true'`, and the client reads
`CLICKHOUSE_HOST`, `_USER`, `_PASSWORD` and `_DB`. `deployment/config/production.env`
sets all five, and `scripts/deploy.sh` reads them to run the ClickHouse
migrations, so the migration step worked. But SST passes the deployed
function only what `sst.config.ts` lists, and it listed none of them. No
Lambda talks to ClickHouse; the sync, the readers, MCP and the digest all
run in the web app. The same class as KB-202, where a Lambda missed the
storage settings.

**After the fix is deployed:** figures start with the first hourly sync.
YouTube's Analytics API returns its recent window and the Reporting CSVs
backfill further; Instagram and Facebook lifetime figures start from their
first snapshot, so their day-by-day changes begin the day after.
