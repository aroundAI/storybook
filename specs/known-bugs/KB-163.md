## KB-163 — Facebook's two-year window is anchored on publish in the capability matrix and restated, on the request, in self-benchmarking

> **Fixed (2026-10-02), #TBD.** `FACEBOOK_VIDEO.window` in the capability
> matrix is `{ maxAgeDays: 730, anchoredOn: 'request_date' }`, as Meta
> documents it, and `VIEWS_DATA_WINDOWS` reads Facebook's window from the
> matrix like every other platform's. A test fails any platform whose window
> is not the matrix's own object, so a literal copy fails even when its
> values agree. Two mutation guards (`tooling/mutation-guards/kb-163.json`)
> restore each half and go red.

**Severity:** Low. Nothing a creator sees is different today: the furthest
benchmark checkpoint is 365 days, inside 730 under either anchor. But the two
statements disagreed, and a fix that only pointed self-benchmarking at the
matrix would have carried the wrong anchor into `predates_ingest`. That reason
tells a creator whether connecting sooner would have recovered a figure. A
publish anchor says it would not, which is untrue for Facebook. **Found:**
2026-10-02, by the FILM-1727 teammate, while moving X's window into the
matrix.

### What was wrong

- `packages/clickhouse/src/lib/data-provenance.ts`, `FACEBOOK_VIDEO`:
  `window: { maxAgeDays: 730, anchoredOn: 'publish_date' }`. This entry is
  spread into every Facebook entry of the matrix.
- `packages/clickhouse/src/lib/self-benchmark.ts`, `VIEWS_DATA_WINDOWS`:
  `facebook: { maxAgeDays: 730, anchoredOn: 'request_date' }`, written out by
  hand and citing the capability reference's summary table. The other four
  platforms already read `capabilityFor('engagement', p).window`.

Reproduced as two failing tests before the fix (`packages/clickhouse`):

```
× takes every platform's window from the capability matrix, never a restated copy
  AssertionError: facebook: expected { maxAgeDays: 730, …(1) } to be { maxAgeDays: 730, …(1) } // Object.is equality
× counts Facebook's two years back from the request, not from publish (KB-163)
  AssertionError: expected { maxAgeDays: 730, …(1) } to deeply equal { maxAgeDays: 730, …(1) }
```

### Which side was right

Meta's documentation measures the limit back from the time of the request,
not forward from when the video was posted. Read on 2026-10-02:

- [video_insights reference](https://developers.facebook.com/docs/graph-api/reference/video/video_insights/),
  Limitations: "Data is only available for the past 2 years."
- [Insights reference](https://developers.facebook.com/docs/graph-api/reference/insights/):
  "Only the last two years of insights data is available." It also says
  "lifetime" means "the time period for which the insights data is available.
  By default, this time period is 2 years or shorter."

Neither page says a video's insights end two years after it was posted. So
the matrix was wrong, and self-benchmarking had the right value but kept its
own copy of it. That copy is the class of bug: FILM-1727 had already removed
X's.

Not changed: Instagram media insights stay `publish_date`, marked inferred.
The media insights page says only "Metrics data is stored for up to 2 years"
(read 2026-10-02), and the reference's ledger records that reading as
inferred. Self-benchmarking already took that window from the matrix.
