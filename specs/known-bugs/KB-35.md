## KB-35 — Semantic previous-episode search never ran in the LLM worker

> **Fixed (2026-09-25), #377.** Built, on the owner's decision. The story
> and story-refinement prompts now get the memory horizon's window of
> earlier episodes — project-wide, across seasons; none for news — as the
> three most recent plus up to three earlier ones most similar to the episode
> being written (`voyage-3-large`, 1024 dimensions, similarity ≥ 0.5).
> Embeddings are written by the worker when it reads them, keyed by a hash of
> the model and the text, so every writer of a story is covered and there is
> nothing to backfill. No key, or any Voyage failure: the recent episodes
> only, one log line, the job succeeds. Building it found two more reasons it
> never ran: nothing ever wrote an embedding (`indexEpisode` had no callers;
> the `pg_notify` trigger had no listener), and the client read
> `response.embeddings`, which Voyage does not return. The trigger, its
> function, the ivfflat indexes and `search_similar_episodes` are dropped;
> `match_episode_embeddings` is service-role only; `premise_embedding` and
> `story_embedding` are kept untouched until production's counts are known
> (the migration prints them). `@kit/embeddings` is deleted.

**Severity:** Low — a feature gap, not a regression: story prompts have always
used the sequential previous episodes. **Found:** KB-14, 2026-09-23.
**Fixed** in #377. The dead code was removed in KB-14's PR; this entry records the gap.

`buildEpisodeContext` (`apps/web/lambda/llm-worker/utils/context-builder.ts`)
had a branch that fetched thematically similar episodes through
`@kit/embeddings/voyage-client` when called with `useSemanticSearch = true`.
It could not run, three ways over:

- **No caller turned it on.** All six callers (`story-ideation`,
  `story-generation`, `shot-generation`, `screenplay-conversion`,
  `story-refinement`, `screenplay-refinement`) used the default `false`.
- **The module does not resolve from the worker.** `@kit/embeddings` is not a
  dependency of `apps/web` (`require.resolve` fails from there; TS2307 under
  KB-14's check). esbuild downgrades an unresolvable `import()` inside `try`
  to a warning, so the bundle would have thrown at runtime and fallen back.
- **It would have thrown if it had resolved.** `voyage-client.ts` imports
  `server-only` and calls `getSupabaseServerAdminClient`, both Next-side.

### Proposed fix

If semantic continuity is wanted: a worker-safe embeddings client (no
`server-only`, the worker's own service client), a dependency the bundle can
resolve, and callers that opt in — then a test that the similar episodes reach
the prompt.

### Acceptance criteria

- [x] Owner decides whether semantic previous-episode context is wanted (2026-09-25: build it)
- [x] If so: one caller opts in and a test shows similar episodes in the prompt (story generation and refinement; `previous-episodes.test.ts`)
