## KB-177 — Prompts moved into generation stages lost the static placeholder and variable checks

> **Fixed (2026-10-03), #569.** The registry test in
> `packages/features/generation/__tests__/stages.test.ts` ("every registered
> stage renders its prompt with the context prepare() builds") now records
> every `buildBrief` input each stage's `prepare()` makes, and fails on:
>
> - a variable the template's text never places (`{{name}}`), declared or not;
> - a placeholder left with no value and no default;
> - a key sent to the stage's quality rubric that the rubric never places.
>
> A last test fails unless every key in `stageRegistry` was checked, and the
> registry holds at least the ten stages on main (parts A, B and C). A stage added later is
> covered by adding its fixture target to the same loop, which the loop
> already demands (`add a fixture target for <key>`).
>
> **What it found.** Merged locally onto #561, it fails the shots stage:
> `scene-shot-generation: sends "reel_note", which it never reads`. The
> template declares `reel_note` but never places it, so the Reel Scout's
> priority note has never reached the model, on main either. Filed as
> **KB-178**. On #562 (story, ideation, season_outline, season_analysis) it
> passes with no change.

**Severity:** Low — a test gap, not a defect a user sees; it hid KB-178.
**Found:** t1902a, while lowering the prompt scans' floors in #554.

FILM-1901 (#557, #560) moved five prompt calls into `@kit/generation` stages:
`story-refinement`, `screenplay-refinement`, `batch-translate-metadata`,
`screenplay-quality` (the rubric) and `extract-asset-description`. A stage
imports its prompt JSON and passes variables to `buildBrief`, as a literal, a
local (`variables,` in #562), a helper's result (`screenplayPromptVariables(…)`)
or a wrapped literal (`sanitizeStrings({…})` in #561).

`prompt-engine/__tests__/prompt-variables.test.ts` (KB-126) reads only calls
with `templateSlug: '…'` and a literal `variables` object, so it saw none of
these. What stayed covered, and what did not:

| Rule | Before |
|---|---|
| A placeholder with no value and no default | Caught at run time: `renderTemplate` throws, and the registry loop called `prepare()` for every stage |
| A placeholder the template does not declare | Same, and prompt-engine's "every template declares every placeholder" |
| A key the template never reads | **Unchecked.** The worker re-renders `brief.prompt.variables`, and the data goes nowhere |
| A rubric key the rubric never reads | **Unchecked.** `renderQualityRubric` fills what is missing on purpose and ignores the rest |
| An empty registry | **Unchecked.** The loop would have generated no tests |

**Why dynamic, not an AST scan.** The variables reach `buildBrief` in four
shapes today, and a scan that cannot resolve one would skip it. Recording
what `prepare()` actually passed reads every shape, and the floor test fails
when a registered stage was not checked, so it cannot pass on an empty set.

**KB-107 does not carry over.** KB-107 and its other side, KB-115, are a
caller reading a field the executor's result does not have, which reads as
`undefined` and fails silently. A stage never reads the model's reply
directly: `runStage` parses it with the stage's `outputSchema` before
`check()` and `commit()`, which are typed by that schema, so a wrong read is
a type error and a wrong shape is a `StageOutputRejected`. Each worker
`generate` returns the executor's `result.data` whole. The one stage prompt
with a `wrapper_key`, `season-outline` (#562), is not run through the bare
executor: its `generate` wraps the orchestrator's array back as
`{ episodes }`, and an external agent writes `brief.outputSchema` directly.
The orchestrator skills those handlers call still use literal slugs, which
`prompt-format.test.ts` checks as before.

**#554's floors stay needed.** The two prompt-engine scans cover the callers
that are not stages: the episodes skills, the app's actions and the Lambda
helpers. This test covers the stages, so a call that moves into a stage
leaves one scan and enters the other.

Red runs (each planted in `story-refinement`, then restored):

| Planted | Result |
|---|---|
| `prepare()` also sends `season_premise` | `story-refinement: sends "season_premise", which it never reads` |
| The template places a declared `{{tone_notes}}` with no default | `PromptTemplateError: Prompt story-refinement cannot be rendered: unfilled {{tone_notes}}` |
| The rubric is also sent `feedback` | `story-quality (rubric of story_refinement): sends "feedback", which it never reads` |
