## KB-125 — A news search asks NewsAPI once per built-in source and credits every article to one of them

> **Fixed (2026-09-25), #400.** One `NewsAPIProvider` now serves every NewsAPI
> source. A search is one `/v2/everything` request with `sources=` listing
> each row's `config.source_id`. Each article is credited to the row whose
> NewsAPI id it carries, at that row's tier. An article from a source not
> asked for is dropped rather than guessed. A row with no `config.source_id`
> is skipped with a warning.

**Severity:** Medium. Every live news search spent 12 NewsAPI requests on the
platform's `NEWSAPI_KEY`, where one would do. NewsAPI's published Developer
plan allows 100 requests a day, so about 8 uncached searches would exhaust it.
That limit is from NewsAPI's documentation; it was not measured here. Worse
for the product: every article was
credited to one source at that source's tier. A BBC story reached the Facts
pipeline as a **Reuters, tier-1** source. **Found:** KB-37 (2026-09-25),
reading the aggregator; lead `leads/2026-09-25-kb-37.md`.

### Reproduced (2026-09-25, `fix/kb-37-team-owned-research-sources` at `a31c949b`)

The real aggregator and `NewsAPIProvider`, with the 12 built-in rows as the
seed migration writes them, an empty cache, and a local NewsAPI stub reached
through `VENDOR_URL_NEWSAPI` (`__tests__/newsapi-one-request.test.ts`). The
stub returned one Reuters and one BBC article:

| Measure | Before | After |
|---|---|---|
| NewsAPI requests per live search | **12**, none with `sources=` | **1**, `sources=` the 12 ids |
| The BBC article's source and tier | **`row-reuters`, `tier_1`** | `row-bbc-news`, `tier_2` |

Why: the aggregator built one provider per row, and a provider took only the
row's id and tier. Each one asked NewsAPI the same unfiltered question and
stamped its own id on every answer; `deduplicateContent` kept the first.

### Acceptance criteria

- [x] Unit, red first: one NewsAPI request per live search, with `sources=` naming every built-in
- [x] Unit, red first: each article is credited to its own row, at that row's tier
- [x] Mutation guards (`tooling/mutation-guards/kb-125.json`): no `sources=`; one provider per row; every article credited to one row. All red
