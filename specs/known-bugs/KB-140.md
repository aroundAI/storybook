## KB-140 — create_character_with_details fails on every call: it writes a column that was renamed

**Severity:** Low. Nothing in the application calls the function today
(`git grep create_character_with_details` finds only the generated types), so
no user sees it fail; but FILM-103 lists it as a transaction function, and
anyone who wires it up gets an error on the first call. **Found:**
2026-09-30, writing the FILM-103 pgTAP test for it.

The function (`20251207165513_film-studio-functions.sql`) inserts into
`character_details` with a `voice_asset_id` column. Migration
`20251225160000` renamed that column to `elevenlabs_voice_id` (text), and the
function was not updated.

### Reproduced (2026-09-30, local database, `main` e7a87fe1)

As a project owner:

```sql
select public.create_character_with_details(<project>, 'Mara', 'd', '{}'::jsonb, 'p', 'e', array['u']);
-- ERROR: Failed to create character: column "voice_asset_id" of relation "character_details" does not exist
```

The function's own `exception when others` turns it into that message, and
the transaction rolls back, so nothing is left half-written.

### Proposed fix

A migration that replaces the function: drop `p_voice_asset_id uuid`, take
`p_elevenlabs_voice_id text` (or none), and write `elevenlabs_voice_id`.
Then extend `transaction-functions.test.sql` with the success path and the
rollback, which FILM-103's two remaining test items wait on.

### Acceptance criteria

- [ ] The function creates an asset and its details in one call (pgTAP, red first)
- [ ] A failure inside it leaves neither row (pgTAP)
