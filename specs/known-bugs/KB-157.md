## KB-157 — A failed publish shows the user raw token codes

> **Fixed (2026-10-01), #510.** Every token code now goes through one map,
> `tokenErrorMessage` (`packages/features/publishing/src/lib/token-errors.ts`),
> which words it as one sentence: what happened, and what to do ("Your YouTube
> connection has expired. Reconnect YouTube in Settings → Platforms to
> publish."). `TokenRefusal` returns that sentence as a refusal, so production
> does not redact it, and carries the code for logs, the stored record
> (`metadata.errorCode`) and a `data-error-code` attribute for support. Rows
> stored with a bare code before the fix are worded when they are read. The
> fix also found two more shapes of the same bug: the publish worker
> wrote its own ad-hoc strings ("Platform connection is inactive", "Failed to
> decrypt access token"), and the app's token check let a stored token it
> could not decrypt throw a raw crypto error into the publish dialog. Both now
> go through the same map (`NO_ACCESS_TOKEN`, `TOKEN_UNREADABLE`).

**Severity:** Low. Nothing is lost and the publish was correctly refused, but
the person publishing reads `NO_REFRESH_TOKEN` and is not told to reconnect
the channel, which is the one thing that fixes it. **Found:** 2026-10-01,
during FILM-1729 (#495), whose `publish-error-inline.spec.ts` asserted the
dialog showed exactly those codes.

### Where a code reached the person

| Surface | Before |
|---|---|
| Publish dialog, inline reason (`publish-platform-error`) | the code, e.g. `NO_REFRESH_TOKEN`, then `CONNECTION_INACTIVE` on the second attempt |
| Published Content record (`published-content-error`) | `metadata.error` as the scheduled job and the publish worker stored it: the bare code, or the worker's own strings |
| Retry (publish hub toast) and LinkedIn post publish | the code was thrown, so a production build showed its generic sentence; a dev build showed the code |
| Platforms page, Refresh button | the same: thrown, so redacted to the fallback toast |
| Publish worker notification (`publish-error` event) | the worker's ad-hoc strings |

The analytics sync crons also keep the code (`metadata.sync.last_error`); no
page renders it, so it stays a code for the operator.

### Reproduced (2026-10-01)

`apps/e2e/tests/publishing/publish-error-inline.spec.ts`, changed to assert
the sentence, run against a production build of the commit before the fix
(`33a7e054f`, lane B, port 3330):

```
1) publish-error-inline.spec.ts:64 › after a failed publish, and again after a second one
   Expected string: "Your YouTube connection has expired. Reconnect YouTube in Settings → Platforms to publish."
   Received string: "NO_REFRESH_TOKEN"
2) publish-error-inline.spec.ts:142 › a failure stored as a bare code reads as a sentence in Published Content (KB-157)
   Expected string: "Your YouTube connection has expired. Reconnect YouTube in Settings → Platforms to publish."
   Received string: "NO_REFRESH_TOKEN"
2 failed
```
