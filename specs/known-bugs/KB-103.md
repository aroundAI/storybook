## KB-103 — The budget check lets a generation through when its RPC errors

> **Fixed (2026-09-25), #374: resolved by removal.** The owner decided
> to remove the budget machinery ("Remove the budget machinery"), so there
> is no check left to fail open. Filed so that the finding is recorded.

**Severity:** Low. A cap existed only if an account's owner set one over
the API, and none had. **Found:** planning KB-95/96/97 (2026-09-25), by
reading.

`checkAccountBudget` (`packages/features/audio-generation/src/server/voice-queries.ts`
on `main` before the removal) returned `true` whenever the RPC returned an
error ("If the function doesn't exist or there's an error, allow the
generation"). So any database fault turned every cap off, silently: the
only trace was a `console.warn`. KB-42 made the function answer `false`
for callers without access rather than raising, partly because of this
fall-through.

### Acceptance criteria

- [x] No generation depends on a budget check that can fail open (the check is removed)
