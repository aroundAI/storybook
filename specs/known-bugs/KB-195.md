## KB-195 — Every project publishes to every channel on the team

> **Fixed (2026-10-10), #662.** `project_publishing_configs` is now the
> project's channel list: one row per channel (migration
> `20261010040539_project-channels.sql`, unique on project and channel, with
> no language check). `getConnectedPlatformsAction({ accountId, projectId })`
> returns only the project's enabled channels, so the Publish screen lists
> and publishes to those alone. `publishToAllAction` and `retryPublishAction`
> refuse any other channel before a token is read
> (`assertConnectionOfProject`, `project-channels.ts`). A project with no
> channels publishes nowhere (owner, 2026-10-10). There is no fallback to
> every channel. The Publish screen says so and offers **Choose channels**, a
> sheet holding the same picker as Platforms → Destinations and Settings. A
> channel still receives the language version set on the channel itself (owner,
> 2026-10-10). The table's own `language` column is no longer read.
>
> Lead L1 (`specs/plans/KB-30-edd.md` §30;
> `leads/2026-09-23-spec-audit.md`) said the table was edited and never read.
> The channel list is read now. Its default tags, title suffix and
> description template are still not applied, and stay a lead.

**Severity:** High — a team that runs several series, each on its own
channels, cannot publish any of them without posting every episode to every
series' channels. **Found:** the owner, 2026-10-10: ten YouTube channels
connected, four projects, each meant for two of them (EN and HI). The
Publish screen showed about 30 destination channels for one episode.

### What happened

The Publish screen loaded its channels with
`getConnectedPlatformsAction({ accountId })`, a read of every
`platform_connections` row on the account, and grouped them by the
channel's language. Publish Now and Schedule built one upload per channel
whose language matched a video. Nothing on the path read the project.
`project_publishing_configs` (project × channel), edited on the project's
Platforms → Destinations tab and in Settings, was never read.

Reproduced on a local stack: a team with four YouTube channels (two English,
two Hindi) and two projects. The Publish screen of an episode in either
project listed all four, two under each language
(`apps/e2e/tests/publishing/project-channels.spec.ts`, run against the code
before the fix, failed at its first assertion: the empty state never
rendered and four channel badges did).

The picker had its own limits. It offered only the first four channels not
yet added. It allowed one row per channel and language, and its language
check refused Bengali. Insert errors were not checked.

### The fix

- **The list:** `getProjectChannelIds` reads the project's enabled rows.
  `getConnectedPlatformsAction` filters by them when given a `projectId`.
- **The refusal:** `assertConnectionOfProject`, after KB-109's
  `assertConnectionOfAccount`, in `publishToAllAction` (which Publish Now
  and Schedule both call) and `retryPublishAction`.
- **The picker:** `ProjectChannelPicker` lists every connected channel,
  grouped by platform, with its language and a search above eight.
  `setProjectChannelsAction({ projectId, connectionIds })` saves exactly
  that set. A delete or upsert that RLS filters to fewer rows is refused
  (KB-105).

### Evidence

- `publish-queue-authorization.test.ts`: both actions refuse a channel of
  the account that isn't the project's, before any token is read. With the
  check removed, both tests fail.
- `kb105-settings-checked.test.ts`: a save that changed no row is refused.
- `project-channels.test.sql` (pgTAP): one row per channel; a Bengali
  channel is accepted.
- `project-channels.spec.ts` (Playwright):
  1. A project with no channels shows the empty state and no channel.
  2. Choosing one EN and one HI channel lists exactly those, under their
     languages.
  3. A second save that swaps the English channel lists the new pair.
  4. After a reload the database holds the same pair.
  5. Another project is still empty.

  With the filter removed, the spec fails at its first assertion.

### Not in this fix

- The project's default tags, title suffix and description template, and
  `episode_publishing_configs`, are still not applied (lead L1).
- Linking an already-published video (`link_published_video`) is not
  limited to the project's channels: it records an upload, it sends nothing.
- Project analytics still list every team channel in places (KB-169).
