## KB-166 — A null Views total gives Facebook's reason whatever the scope

> **Fixed (2026-10-02), #540.** The reason a null Views figure gives is
> worked out from the scope it covers, never typed per platform
> (FILM-1705's copy rule). `viewsNotMeasuredReason`
> (`packages/features/content-analytics/src/lib/views.ts:67`) goes through
> the scope's platforms in the chips' order. A platform with no views
> column gets its own matrix note: `viewsNote`, new on
> `PlatformCapability` (`packages/clickhouse/src/lib/data-provenance.ts:318`),
> set on Facebook's engagement entry (`:501`). A test binds it to FILM-1722's
> `VIEWS_COLUMN_PLATFORMS`, so a platform gets a note exactly when it has no
> views column. A platform with no rows in the window gets the chip's own
> no-data-in-window line (`coverageLines`). Each sentence appears once, as in
> a chip's body.
>
> The company dashboard (`account-dashboard-actions.ts:219`) and the
> episode, season and project data (`aggregation-queries.ts:328`, `:567`,
> and the project's merge of its seasons) carry a `viewsScope`: the
> platforms of their publishes, and the platforms whose publishes have rows.
> `MetricCards` requires the scope (`metric-cards.tsx:106`), so no caller
> can fall back to Facebook. A caller that cannot say passes null and gets
> a reason that names no platform. `VIEWS_NOT_MEASURED_REASON`, still read
> by the video log's per-video cells, is now built from the matrix notes
> rather than typed.
>
> Evidence: `views-not-measured-reason.test.ts` covers Facebook only,
> YouTube only with no rows, mixed, and the matrix binding. It was red
> before the fix. `metric-cards-views.test.tsx` covers the card with a
> YouTube-only scope, which was red with Facebook's reason. The episode
> and account suites cover the scopes the server builds. In the browser,
> `company-dashboard-evidence.spec.ts` has two tests. "Facebook with rows
> and YouTube without" reads the company dashboard's tooltip. "A
> YouTube-only episode with no rows yet" reads the episode page's tooltip.
> Both were red with the old reason restored ("Received: Facebook counts
> four different kinds of view…"), then green. Screenshots:
> `kb166-1-facebook-and-empty-youtube-team.png` and
> `kb166-2-youtube-episode-no-rows.png`. Guards are in
> `tooling/mutation-guards/kb-166.json`: five unit and two e2e, all red
> under their mutation.

**Severity:** Low. Wherever Views reads "Not measured", the hover explains
it with Facebook's four kinds of view, even where Facebook has nothing to
do with it. A creator with only a YouTube publish and no rows yet is told
the wrong cause. **Found:** 2026-10-02, after KB-162 (#531) gave the Views
card Facebook's reason as its own. The owner approved the fix the same day.

### What happens

KB-162 made a null Views total say "Not measured", with
`VIEWS_NOT_MEASURED_REASON` as its `title`. That constant is Facebook's
sentence. A Views total is also null in these cases:

- On the episode, season and project pages, when no publish has rows. The
  folds start from null and skip a publish with no totals
  (`aggregation-queries.ts`), so a YouTube-only episode with no rows yet
  reads "Not measured" with Facebook's reason.
- On the company dashboard, when every row is Facebook's. If a YouTube
  publish with no rows sits beside them, the reason should name both causes.

The company dashboard does not show a null Views total for a YouTube-only
team with no rows. It shows 0, which is its own bug: KB-167.

Reproduced on this branch's parent with the old reason restored. The two
Playwright tests above failed with `Received string: "Facebook counts four
different kinds of view, …"`, where the YouTube no-data line was expected.

### Acceptance criteria

- [x] A null Views figure's reason comes from the scope's platforms. It
  uses the matrix's views note for a platform with no views column and the
  no-data-in-window line for a platform with no rows. It names no platform
  by hand.
- [x] Facebook only gives Facebook's note. YouTube only with no rows gives
  the no-data line. A mixed scope gives each sentence once, in the chips'
  order.
- [x] The company dashboard and the episode page show that reason on hover,
  asserted in the browser.
