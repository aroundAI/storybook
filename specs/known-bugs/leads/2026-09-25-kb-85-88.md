# Leads from KB-85 and KB-88 (2026-09-25)

Read, not reproduced as bugs. The rule for leads is in [the README](../README.md#leads).

**Public sharing (read while fixing KB-85/KB-88, #357)**
- Sitemap episode URLs can 404: `getSitemapData` builds `/e/<public_slug>`, but the episode page resolves `/e/<x>` by `slug` (`get_shared_episode`, `apps/web/app/(public)/[...slug]/page.tsx`). Whenever an episode's `public_slug` differs from its `slug`, the sitemap lists a URL that 404s. The E2E seeds them equal
- Project covers, genre and audience never show on public pages: the pages read `metadata.cover_url`, `genre` and `target_audience` (`packages/features/public-sharing/src/components/project-page.tsx`, `company-page.tsx`), while the studio stores `coverImageUrl` and `targetAudience` (local database, 2026-09-25: `projectType`, `canon`, `coverImageUrl`, `targetAudience`, …). `public_projects` passes through exactly the three keys the page reads, so fixing the keys means changing the view too
- `apps/web/app/sitemap.xml/route.ts` is dead: `app/sitemap.ts` serves `/sitemap.xml` (its output has `changefreq`/`priority`, which only `sitemap.ts` emits). The route and its unit test can go
- During `next build`, `sitemap.ts` calls `cookies()` through the Supabase client; Next's "Dynamic server usage" bail-out is wrapped by `fetchAllRows` and swallowed by the route's catch ("Sitemap data failed; serving static URLs only" in every build log). The route still renders per request today; if the read ever stopped touching cookies, it would silently become a build-time snapshot

**`anon` reach a migration cannot change (KB-85)**
- `supabase_admin`'s default privileges in `public` grant `anon` everything on new tables, sequences and functions *it* creates (local `pg_default_acl`, 2026-09-25). `postgres` cannot alter another role's defaults on hosted Supabase. Migrations run as `postgres`, whose defaults are fixed; the allowlist in `anon-public-surface.test.sql` fails if a `supabase_admin`-created relation ever grants `anon`
- pgvector is installed in `public`, so its 118 functions are executable by PUBLIC, and so over `/rest/v1/rpc` by `anon` now that it has USAGE. They are pure math over their arguments and touch no table. Moving the extension to `extensions` would remove them
- `anon` holds Supabase's default full grants in `storage` (local `pg_default_acl`); storage is governed by its own RLS policies and was not audited here
