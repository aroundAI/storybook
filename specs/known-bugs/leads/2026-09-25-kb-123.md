# Leads from KB-123 (2026-09-25)

Read, not reproduced. The rule for leads is in [the README](../README.md#leads).

**`localized_videos` holds two shapes, written by two features** (found by KB-123, 2026-09-25)
- Publishing stores `{ "<lang>": "<video file URL>" }` (`updatePublishedVideoAction`). Public sharing stores `{ "<lang>": { youtube: { url, … }, facebook: { url, … } } }` in the same column (`updateLocalizedVideosAction`, `updateEpisodePublicSettingsAction`, `packages/features/public-sharing/src/server/visibility-actions.ts`), and its public pages read that shape (`public-queries.ts`, `video-player.tsx`, `metadata.ts`, `structured-data.ts`).
- Both public-sharing writers have no caller in the app (`VideoLinkManager` is mounted nowhere), so today the column holds publishing's strings. The public pages then read a string as an object, and would show no video.
- If either writer is ever mounted, saving it replaces publishing's videos with objects. KB-123's resolver skips non-string values, so a publish would then find no video rather than send an object.
- The fix is a column per shape, or one shape.

**Publish-now ignores the Shorts group the user chose** (found by KB-123, 2026-09-25)
- `publishToAll` stores `shortsGroupId` in the publish's metadata, but uploads the **first** group that has a video for the language. With two groups in one language, publish-now can send the other group's short, while the scheduled paths use the named group.
- KB-123 kept this behaviour on purpose (`PUBLISH_NOW_PRECEDENCE`), because changing it would change what publishes. **Filed and fixed as KB-133** (2026-09-27): the owner's intended behaviour is that every short is published, so publish-now now uses the group it names.

**The three publish paths pick a video differently** (found by KB-123, 2026-09-25)
- For a short, the scheduled Lambda needs the group and never falls back. The in-app scheduled job falls back to the full video. Publish-now falls back too, and for a full publish it also falls back to a short.
- `resolveEpisodeVideo` makes the three precedences visible in one file (`SCHEDULED_LAMBDA_PRECEDENCE`, `SCHEDULED_JOB_PRECEDENCE`, `PUBLISH_NOW_PRECEDENCE`). Choosing one precedence is a product decision.

**Shorts group edits are optimistic** (found by KB-123, 2026-09-25)
- The publish screen updates its group list before `updateShortsGroupsAction` answers. A refused save (now possible, KB-123) shows a toast but leaves the screen showing the unsaved change until reload.
- Through the UI a refusal needs a group already holding a video that isn't the episode's, which production does not have (the KB-123 count).
