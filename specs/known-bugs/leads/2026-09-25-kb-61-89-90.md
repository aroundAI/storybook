# Leads from KB-61, KB-89, KB-90 (2026-09-25)

Read, not reproduced. The rule for leads is in [the README](../README.md#leads).

**Other places that store a client-supplied URL as a file** (found by KB-90, 2026-09-25; the publish request's `thumbnailUrl` was reproduced and is KB-104)
- Schemas that accept any URL as a stored file: `apps/web/app/api/projects/[projectId]/shots/[shotId]/upload/route.ts:63-64` (`videoUrl`, `thumbnailUrl`), `packages/features/assets/src/lib/schemas/asset.schema.ts:101` (and `:116`, `:166`, `fileUrl`/`thumbnailUrl`), `packages/features/assets/src/lib/schemas/character.schema.ts:71-72`, `packages/features/audio-generation/src/server/audio-asset-actions.ts:155` (`fileUrl`). Whether anything later fetches or deletes by these URLs was not traced. `ownedStorageKey` (`@kit/storage`) is the check each would adopt. (`packages/features/audio-generation/src/lib/schemas/lip-sync.schema.ts:32` is in the lip-sync feature being retired.)

**`canEditEpisode` is a second copy of the project-write rule** (found by KB-89, 2026-09-25)
- `packages/features/episodes/src/server/thumbnail-actions.ts` checks project membership with role `owner | admin | member` through a join, rather than `can_write_project`. It agrees with the rule today; KB-89 is what happens when a copy and the policy drift apart. Replacing it with the RPC removes the copy.

**`setDefaultThumbnailAction` unsets the old default before setting the new** (found by KB-89, 2026-09-25)
- Two updates, neither checking what it changed (KB-105's shape): if the second is refused or fails, the episode is left with no default. One statement, or a function, would make it atomic.
