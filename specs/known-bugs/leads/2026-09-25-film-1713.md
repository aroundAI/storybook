**From FILM-1713 (2026-09-25), found while building velocity at daily grain**
- Hourly early-warning velocity (the spec's 0–1h … 24–48h buckets) needs its own storage spec. It is not a query change. `video_snapshots` is `ReplacingMergeTree(fetched_at)` ordered by `(project_id, platform, video_id, snapshot_date)` (`packages/clickhouse/src/migrations/002_metrics_v2.ts:59-60`), so each hourly sync overwrites that day's row and only the day's last fetch survives. `video_metrics` is keyed by `metric_date`. Sub-daily history would need a per-fetch key (e.g. `fetched_at` in the sort key, or a separate table), a retention decision for it, and a check of vendor rate limits against an hourly per-video fetch. The owner chose the daily grain for FILM-1713 (Q2, 2026-09-25) and asked for this to be filed separately.
