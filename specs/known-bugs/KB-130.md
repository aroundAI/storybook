## KB-130 — A shot list with a fractional shot duration fails to save: the prompt allows 8.35, the column is an integer

> **Fixed (2026-09-25), with FILM-1806.** `wholeShotSeconds`
> (`packages/features/episodes/src/lib/schemas/shot-list.schema.ts`) rounds
> to whole seconds, at least one, and every writer of the column uses it:
> the shot-generation worker and the create, batch-create and update shot
> actions. `packages/features/episodes/__tests__/shot-duration.test.ts`
> checks the function and scans both files for any other write; it went red
> on both files without the fix.

**Severity:** Medium. Shot generation is the step between an approved
screenplay and everything visual and audio after it. When it fails, the
episode stays on "Visual Studio Locked", and a retry can hit the same thing.
**Found:** FILM-1806, driving a full studio run through the local job queue
against the AI sandbox, 2026-09-25.

`scene-shot-generation`'s schema declares `duration: z.number().min(3).max(10)`,
so 8.35 is a valid answer. `shots.duration_seconds` is `integer`, and
Postgres refuses the whole batch:

```
[LLM Worker] Job failed: Error: Failed to insert shots:
invalid input syntax for type integer: "8.35"
[Job Tracking] Marked shot_list as failed
```

The same holds for the shot actions: `CreateShotSchema`, `BatchCreateShotsSchema`
and `UpdateShotSchema` accept `z.number().positive().max(10)`, so an edit to
7.5 seconds failed on the write too.

It is the only integer duration column fed by a model. The others
(`audio_cues`, `dialogue_lines` and `shot_transitions`) are `numeric`.

### Acceptance criteria

- [x] Every write of `shots.duration_seconds` stores whole seconds. Seen red
  first (`shot-duration.test.ts`, both writers).
- [x] A shot list generated through the local job queue saves, and the
  visual studio opens on it (`apps/e2e/tests/sandbox/studio-flow-evidence.spec.ts`).
