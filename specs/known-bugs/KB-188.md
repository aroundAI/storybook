## KB-188 — The story orchestrator writes episodes.viral_quality mid-run, so the story commit is refused TARGET_CHANGED

> **Fixed (2026-10-04), #607.** The orchestrator no longer writes the
> episode (`packages/features/episodes/src/agent/story-orchestrator.ts`); it
> returns the score, and the story stage's commit writes `viral_quality`
> beside `story_data` in the run's one transaction
> (`packages/features/generation/src/stages/story.ts`). Migration
> `20261004101714_kb188-story-viral-quality-allowlist.sql` adds the column
> to `kit.generation_commit_allowlist()`; pgTAP
> `kb188-story-viral-quality.test.sql` shows the mid-run write refusing the
> commit (V1) and the score committed with the story (V2, red without the
> migration: "viral_quality is not a column a generation commit updates in
> episodes"). The sandbox orchestrator test now refuses an `episodes` update
> from the orchestrator (red with the old one).
> `apps/e2e/tests/sandbox/story-after-ideation.spec.ts` was red on main at
> the first story and passes on the fix, beside FILM-1804's full studio
> flow.

**Severity:** High — every server-mode story generation fails at its
commit: the user clicks Generate Story, the orchestrator writes a story,
and nothing is saved. **Found:** reading the story path while fixing KB-186,
then reproduced against the AI sandbox.

**What happens.** Generate Story opens a server run for the `story` stage
with `target_version` set to the episode version the page sent
(`generateFullStoryAction` → `openRunForJob` → `jobRunTarget`). The Story
Orchestrator then stores its viral score with `update episodes set
viral_quality = …` (story-orchestrator.ts, before this fix). The
`episodes_increment_version` trigger bumps the version on every update, so
by the time the stage commits, the episode is one version ahead of the run.
`assertTargetUnchanged` and `apply_generation_commit` both refuse with
TARGET_CHANGED, the job is marked failed, and the page stays where it was.
Nothing reads `episodes.viral_quality`; the story commit already carried
the score in `story_data.viralQuality`.

**Reproduced.** Local queue, the app's llm-worker and the AI sandbox, on
main 36bfc6223, running `story-after-ideation.spec.ts`. The worker log:
`[Story Orchestrator] viral_quality persisted`, then `RunError: Episode … is
at version 3; run … was briefed on version 2` (`code: 'TARGET_CHANGED'`)
from `RunHandle.assertTargetUnchanged`; the spec stayed on `/ideation`.

**Acceptance criteria.**
- [x] A server-mode story commits after the orchestrator has scored it, and
      the score is stored on the episode.
- [x] The orchestrator writes nothing to the episode during the run.
