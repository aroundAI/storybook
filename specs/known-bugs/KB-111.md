## KB-111 — TikTok and Instagram rows store 0 for metrics those platforms never measure, and it is pooled as measured

> **Fixed (2026-09-25), #388.** ClickHouse migration `013_unmeasured_is_null`
> makes the four columns `Nullable` with no default, recreates the
> `video_daily_stats` view, and sets existing TikTok/Instagram values to NULL.
> The owner approved it (decision #32); the owner runs it on production at
> deploy. The TikTok/Instagram writer (`buildSnapshotDeltaRow`) pins the four
> to `null` in its type. `queryQualityMetricsForVideos` weights each average
> by the views of the days that carry it and returns `null`, never 0, and
> `queryNetSubscribersForVideos` returns `lost: null`. Per decision #33 (A),
> `foldViewWeighted` and `foldNetSubscribers` leave unmeasured videos out, and
> the panel's existing "N of M videos had data" label now counts only the
> videos that measure the figure. Measured on ClickHouse 24.8 first:
> `MODIFY … Nullable` keeps `DEFAULT 0` (hence `REMOVE DEFAULT`); the plain
> view keeps its old types and **fails every read** once a NULL exists (hence
> the recreate, before any NULL); and a one-step rollback wedges the table
> (the migration header gives the two-step one). TikTok's `subscribers_gained`,
> watch-time and saves zeros are **KB-114**.

**Severity:** Medium — a displayed figure breaks the rule that "cannot
measure" is not "measured badly". Average percentage viewed and net
subscribers are wrong for any set of videos that mixes YouTube with TikTok or
Instagram. **Found:** KB-94's investigation, 2026-09-25. **Reproduced.**

The TikTok and Instagram sync (`ingestCumulativeSnapshot` in
`analytics-sync-cron.ts`) writes a `snapshot_delta` row that has no
`avg_view_percentage`, `subscribers_lost` or `dislikes`. Neither platform
reports them on any surface we ingest. The columns are `Float32 DEFAULT 0` /
`UInt32 DEFAULT 0` (migrations 004 and 006), so the row stores a 0. That 0 is
not a clobber (there is one writer per key, unlike KB-94). But every reader
takes it as a measurement:

- `queryQualityMetricsForVideos` returns `avgViewPercentage: 0` for a TikTok
  video, and does not report the figure as absent;
- `foldViewWeighted` (the Experiments and Change Log watched metric "Average
  percentage viewed") weights that 0 by the TikTok video's views;
- the net-subscriber readers (`queryNetSubscribersForVideos`,
  `queryWatchWindowTotals`, `querySubscriberDeltas`) read `lost = 0`. For
  Instagram, whose `subscribers_gained` comes from `follows`, net therefore
  equals gains. TikTok writes `subscribers_gained: 0` as well
  (`analytics-sync-cron.ts`, "TikTok doesn't provide per-video follower
  gains"), so its net reads as a measured 0 when it is not measured at all.
  That makes it a fourth column in the same state.

Reproduced on `ddc5568a` with a throwaway ClickHouse 24.8.14.39. It had the
real migrations and the rows were written by the real `insertVideoMetrics`. The
row was built as `ingestCumulativeSnapshot` builds it: one YouTube video
(average percentage viewed 45.5, 400 views) and one TikTok video (1,000 views):

```
TIKTOK (never measured): {"avgViewPercentage":0, ...}
watched-metric AVP pooled over both: {"status":"measured","value":13,"coveredVideos":2}
```

The net-subscriber half was read in the code, and not run.

The honest answer is 45.5% over one covered video. The panel says 13%, over
two.

**Proposed fix** (an EDD comes first; it is ClickHouse DDL):
- make the three columns `Nullable`, and decide the same for TikTok's
  `subscribers_gained`, (`ALTER TABLE video_metrics MODIFY COLUMN …`,
  after `engaged_views` in migration 012). The TikTok and Instagram writer sets
  them to `NULL`, and both YouTube writers keep setting them (KB-94's
  `YouTubeVideoMetric`);
- make the readers skip NULL. That means the view-weighted averages take their
  denominator from `views` where the figure is not NULL. `foldViewWeighted`
  then counts only the videos that carry the figure. Net subscribers report
  losses as unknown for a platform that has none, and do not report 0;
- existing TikTok and Instagram rows: set the three to NULL by
  `platform`/`metric_source`. That is safe because no source ever measured them.

**Acceptance:** with one YouTube video (45.5%, 400 views) and one TikTok video
(1,000 views), the watched metric reads 45.5% with one covered video, and the
TikTok video's average percentage viewed reads as not measured. This is
asserted in `verify-queries.ts` and in `watched-metrics` unit tests, each seen
red first.
