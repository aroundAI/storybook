## KB-131 — A title containing `</script>` ends the public page's JSON-LD script early, and what follows runs as markup

**Severity:** High. The public pages put structured data in
`<script type="application/ld+json">` as bare `JSON.stringify` output. JSON
does not escape `<`, and the HTML parser ends a script element at the first
`</script>` whatever JSON thinks of it. A team, project or episode title
containing `</script><script>…</script>` closed the element early, and the
second script ran for every visitor to the public page. Any signed-in user
writes those titles. **Found:** 2026-09-25, reading the public page's
`dangerouslySetInnerHTML` sites while checking the invite email for the same
shape.

Five sites wrote JSON-LD this way: three in the public catch-all page
(`apps/web/app/(public)/[...slug]/page.tsx`), one on the FAQ page, and `JsonLd`
in `apps/web/lib/structured-data.tsx`.

### Fix

`serializeJsonLd` (`apps/web/lib/json-ld.ts`) escapes `<`, `>` and `&` as
`<`, `>` and `&`, plus U+2028 and U+2029. A JSON parser reads
the same value, and the HTML parser has nothing to act on. Every site now
renders through `JsonLd`, which calls it. `json-ld.test.ts` fails on a
`JSON.stringify` passed to `dangerouslySetInnerHTML` anywhere else in the web
app.

The invite email has the same shape: an i18n string with markup, rendered
with `dangerouslySetInnerHTML`, holding the team and inviter names. It
already escapes them. `invite-email-escaping.test.tsx` now holds it to that.
