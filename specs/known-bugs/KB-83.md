## KB-83 — Voice spend is never counted against the monthly budget

> **Note (2026-09-25): the budget machinery is removed, #374.** The owner
> decided to remove it ("Remove the budget machinery"): the cap defaulted to
> NULL and nothing in the app could set it, so it never limited anything.
> `increment_account_usage`, `current_usage_cents` and KB-83's clause in `kit.protect_account_fields` are dropped. This fix stays recorded as it was; its guards are retired with
> the code they guarded.

> **Fixed (2026-09-24), #351.** Voice spend is recorded with the
> server's client, for the account the action authorised, and by the voice
> worker; the RPC stays service-role only and refuses negative amounts; and
> no API role can write `current_usage_cents` directly. Design:
> `specs/plans/KB-73-79-83-edd.md` (KB-73/79 shipped in #350).

**Severity:** Medium: the budget cap cannot stop spending it never sees.
**Found:** KB-46 (2026-09-24); **reproduced** against the local DB: every role,
the owner included, gets 42501 calling `increment_account_usage`.

`increment_account_usage` is granted to `service_role` only
(`apps/web/supabase/migrations/20251211090557_add-account-budget-tracking.sql:53`).
The preview and single-line voice actions call it with the user's client
(`voice-actions.ts`, then `voice-queries.ts` `incrementAccountUsage`), which
logs the 42501 and carries on. So their spend never reaches the account's usage
total, and `check_account_budget` keeps answering yes.

**Bigger than recorded** (audio-lib, 2026-09-24):

- **The voice worker never counted anything.** Batch and queued single-line
  voice are most voice spend, and `apps/web/lambda/voice-worker/voice-generation.ts`
  wrote a `costCents` into the line's metadata and never called the RPC, so
  fixing the grant alone would have counted only the synchronous paths.
- **The owner could already lower usage without the RPC.** Reproduced in a
  rolled-back transaction as a personal account's owner (`authenticated`):
  `update accounts set current_usage_cents = -1000, monthly_budget_cents = null`
  returned `UPDATE 1`, `-1000 | null`. `accounts_self_update` allows the
  primary owner to update the row, and `kit.protect_account_fields` did not
  cover the column. So "no user can decrement usage" was false whatever the
  RPC's grant.

### Fix (how the counter stays honest)

- **The RPC is not granted to `authenticated`.** A grant, even behind an
  account check, would let any writer on a team call it with any amount and
  use up the team's budget. `recordVoiceSpend(target: LlmJobTarget, cents)`
  calls it with the server's client; an `LlmJobTarget` comes only from KB-46's
  authorisers, so the account is one the caller may write, never one a
  request names. The amount is the provider's cost or the server's estimate.
  Zero, negative and non-finite amounts are skipped.
- **The voice worker counts each generated line** on the payload's account,
  which the enqueuing action authorised (KB-46/47).
- **`increment_account_usage` refuses a negative or null amount** (22023),
  for the service role too.
- **`kit.protect_account_fields` refuses a change to `current_usage_cents`**
  from `authenticated`/`anon`. The owner may still set their own
  `monthly_budget_cents` (owner decision, 2026-09-24).

### Proposed fix (as filed)

Call it with the admin client after the action has authorised the target
(KB-46's `can_write_project` check now runs first), or grant it to
`authenticated` behind an access check inside the function. Either way, add a
pgTAP case for who may call it.
