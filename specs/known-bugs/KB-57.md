## KB-57 — Audio, report and shorts upload paths have no storage-level project check on R2

> **Fixed (2026-09-25), #359.** Every server-side storage write now goes
> through one gate, `writeProjectObject` in `@kit/storage`, which asks
> `can_write_project_storage` — the function every project storage policy
> runs on Supabase — about the **key itself**, as the caller, before the
> adapter is touched. The presign route's project check is the same
> function. Workers, which have no user session, write only inside the
> target their producer authorised (`uploadToR2`'s required `target`).
> Generated audio keys now name their project or episode
> (`projects/<P>/sfx|music/…`, `episodes/<E>/dialogue|previews/…`); before,
> dialogue, voice previews and generated library audio were written at keys
> no rule could check. A structural test fails on any storage write outside
> the gate (red on 7 files, 9 calls). **No live cross-project write was
> reproduced:** every writer already checked `can_write_project`; the fix
> binds the key to that check. There is no local R2: the gate was exercised
> against the adapter test double and the real R2 adapter with its S3
> client replaced. The **report** leg did not apply to R2 — reports only
> ever go to the private Supabase `reports` bucket (KB-55, owner decision
> D2), behind RLS — and the **shorts** leg was removed by KB-55 (#332).

**Found:** KB-28 (2026-09-23). **Filed by the lead from the teammate's report; not reproduced here.**
**Open** for reports; the shorts path was removed by KB-55 (#332).
**Audio library leg fixed** in #350 (KB-73): reproduced 2026-09-24 — any
signed-in user's call stored a file in the public `audio-assets` prefix,
with the admin client, before the project was checked. The library now
uploads through the presign route (project writers only) and records only a
key inside its own project's folder.

The audio, report and shorts upload paths have no storage-level project check on R2.
