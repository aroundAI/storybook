## KB-173 — A video's benchmark fails whenever its scope names the account

> **Fixed (2026-10-02), #550.** The subject lookup's aliases are now
> `subject_*`, so the scope's `account_id = …` in WHERE reads the column
> again instead of the aggregate. `verify-queries.ts` gained the step
> "self-benchmark: a scope naming the account too reads the same video
> (KB-173)", which failed before the rename and passes after it. Found
> building FILM-1719, the first caller to pass the account.

**Severity:** Medium. Every caller that scopes the benchmark the way the
rest of the analytics reads are scoped (project and account) gets an error
instead of a reading. No figure was ever wrong; the benchmark never
answered. Nothing in production called it with an account until FILM-1719,
which is why it was not seen. **Found:** 2026-10-02, driving the FILM-1719
signal surface against local ClickHouse.

### What happens

`queryVideoBenchmark` (`packages/clickhouse/src/queries-advanced.ts`) reads
the subject video's latest dimensions in one grouped query:

```sql
SELECT toString(argMax(account_id, updated_at)) as account_id, …
FROM video_dim
WHERE ${conditions} AND video_id = {benchmarkVideoId: String}
GROUP BY video_id
```

ClickHouse resolves a name in WHERE to a SELECT alias before it resolves it
to a column. With `scope.accountId` set, `conditions` contains
`account_id = {accountId: String}`, which then means the `argMax`, and the
server refuses it:

```
Aggregate function argMax(account_id, updated_at) is found in WHERE in query.
(ILLEGAL_AGGREGATION, code 184)
```

The same holds for `connection_id` and `platform`. `verify-queries.ts` only
ever passed `{ projectId }`, whose column was not aliased, so every check
passed.

### Reproduced

The FILM-1719 signal surface, which passes `{ projectId, accountId }`,
showed "could not be loaded" for every video; the server log carried the
error above. Calling `queryVideoBenchmark` with the same scope from the
verify script raised it directly.

### The fix

Rename the aliases (`subject_account_id`, `subject_connection_id`,
`subject_platform`, `subject_content_type`,
`subject_asset_duration_seconds`, `subject_language`,
`subject_published_at`) and read those. The other grouped dim reads
(`dimSubquery`, the language read) filter in an inner subquery and were not
affected.

### Acceptance criteria

- [x] A scope naming the account reads the same video as one naming only
      the project: `verify-queries.ts`, "self-benchmark: a scope naming the
      account too reads the same video (KB-173)" (directional, value 500,
      typical 300).
