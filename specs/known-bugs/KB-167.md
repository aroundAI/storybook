## KB-167 — The company dashboard shows 0 views when nothing has been measured (no rows yet, or ClickHouse off)

> **Fixed (2026-10-02), #542.** A views total over nothing measured is
> null, never 0. `queryTotalsSingle` gives null where `row_count` is 0
> (`packages/clickhouse/src/queries.ts:480`), and `NO_ROWS_TOTALS`, which
> ClickHouse off returns, carries `views: null` (`queries.ts:327`). The
> empty company dashboard gives null to both periods
> (`account-dashboard-actions.ts:258`), so no projects, no publishes and a
> failed ClickHouse read all say "Not measured". The card's reason is
> KB-166's: for a YouTube-only team with no rows, "YouTube is connected,
> but has no data for the last 30 days." A row that counted 0 views is a
> measured 0 and still reads 0.
>
> The same class, fixed with it: an episode with no publishes read 0
> views and 0% engagement (`aggregation-queries.ts:150`); a season with
> no episodes or no publishes read 0, and so did each unpublished episode
> (`:395`, `:437`); a content-list publish with no rows read 0 views
> (`:1067`). The language card's change against the previous period read
> +100% when that period had no measured views, KB-16's shape; it is null
> now (`language-analytics.ts:324`) and the card draws no change
> (`language-analytics-cards.tsx:216`). The metric cards' own period
> deltas already treat a null previous figure as no comparison.
>
> Left open, as KB-168: likes, comments and shares still read 0 where
> nothing was measured, and an engagement rate over a measured 0 views
> reads 0%. `PerformanceInsights`, which defaults its change to 0, has no
> importer.
>
> Evidence. Unit tests, each red before the fix with "expected +0 to be
> null" (14 in all): `totals-unmeasured.test.ts` (no rows, ClickHouse off,
> no row sent, and a measured 0), `clickhouse.test.ts`,
> `account-dashboard-unmeasured.test.ts` (no projects, ClickHouse failing,
> a null previous period), `episode-analytics-unmeasured.test.ts`,
> `nothing-measured-views.test.ts` (season, content list),
> `language-analytics.test.ts` ("expected 100 to be null") and
> `language-cards.test.tsx`. verify-queries' KB-167 step
> (`packages/clickhouse/scripts/verify-queries.ts:5181`) seeds one YouTube
> row of 0 views and reads it against ClickHouse 24.8: measured 0, empty
> window, absent publish and 1,500 absent ids across two chunks give
> `[0, null, null, null]`; with the old line it gave `[0, 0, 0, 0]`, and
> the KB-162 step's no-row totals `[0, null, null]`. In the browser,
> `company-dashboard-evidence.spec.ts` "a YouTube-only team with no rows
> yet" reads "Not measured", the no-data reason and Avg Engagement "Not
> measured"; with the old line it failed on the card reading 0. "a

> Guards in `tooling/mutation-guards/kb-167.json`: ten unit and two e2e,

**Severity:** Low. A team whose publishes have no rows yet in the window,
or whose server reads no ClickHouse (production's state today), reads
"Views 0" on its home dashboard. A 0 says "nobody watched", but nothing was
measured. The episode page shows "Not measured" for the same state, so the
two pages disagree. **Found:** 2026-10-02, while fixing KB-166, which
expected a null there and found 0.

### What happens

- `queryTotalsSingle` returns `views: Number(row.row_count) === 0 ? 0 :
  nullableNumber(row.views)` (`packages/clickhouse/src/queries.ts:479`).
  No rows in the window gives 0 views. With ClickHouse off it returns
  `NO_ROWS_TOTALS` (`queries.ts:327`, `views: 0`).
- `getEmptyDashboardData` returns `views: 0` for both periods
  (`packages/features/content-analytics/src/server/account-dashboard-actions.ts:257`,
  `:269`). That covers a team with no projects or no publishes, and the
  `catch` taken when ClickHouse fails. Likes, comments and shares are 0
  there too.

Reproduced on lane B (ClickHouse 24.8) with a dev server on this branch. A
seeded team with one published YouTube video and no `video_metrics` rows
shows a Views card reading `"Views\n0\nNo previous period to compare"`
(probe screenshot `kb167-youtube-team-no-rows.png`, not committed).

### Proposed fix

Views over a scope where nothing was measured is null, in the same way
KB-162 made watch time and follower gain null: no rows, ClickHouse off,
and the empty dashboard. The card then says "Not measured" with KB-166's
reason. Changing this affects several cards and E2E expectations: Avg
Engagement, the platform split, and the KB-162 specs that read
"Views 180". The lead is scheduling it after #531 and KB-166 land.

### Acceptance criteria

- [x] The company dashboard's Views card reads "Not measured", not 0, for
  a team whose publishes have no rows in the window.
- [x] With ClickHouse off, or with no publishes, it does not read 0.
- [x] A measured 0 (rows with 0 views) still reads 0.
