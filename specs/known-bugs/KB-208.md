## KB-208 — The production deploy failed: the web app's Lambda variables passed AWS's 4 KB limit

> **Fixed (2026-10-19), #687.** The `StorybookWeb` environment in
> `sst.config.ts` no longer lists the `NEXT_PUBLIC_*` settings that
> `next build` inlines into the bundle (the anon key, site name, title and
> description, auth and account switches, branding, billing provider, Stripe
> publishable key, Keystatic path, Sentry DSN). It keeps
> `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SITE_URL` (its fallback is
> computed here) and `NEXT_PUBLIC_WEBSOCKET_URL` (an SST output). Test:
> `packages/shared/__tests__/web-env-forwarding.test.ts`, "lists no
> NEXT_PUBLIC_* the build already inlines", red on main.

**Severity:** High. Every deploy stopped: the web app kept running its
previous version, so the fixes in #682–#686 (analytics on, the Shorts cap,
YouTube's length check, publish-now in the worker, deleted episodes) did not
reach it, though the Supabase migrations applied.

**Found:** 2026-10-19, `pnpm deploy:production`:
`InvalidParameterValueException: Lambda was unable to configure your
environment variables because the environment variables you have provided
exceeded the 4KB limit. Measured size: 4156 bytes`.

**Cause:** Lambda limits a function's environment variables to 4 KB in
total. The web function carried every server secret plus about twenty
`NEXT_PUBLIC_*` values, including the Supabase anon key and the Stripe
publishable key. KB-203 (#682) added the five `CLICKHOUSE_*` settings, which
took it over. The `NEXT_PUBLIC_*` values were never needed at runtime:
Next.js replaces `process.env.NEXT_PUBLIC_*` with its value in the server,
middleware and client bundles at build time, and `scripts/deploy.sh` loads
`deployment/config/production.env` into the build's environment (`set -a`),
so the build has them without SST listing them. No internal package is a
`serverExternalPackages` entry, so none reads them unbundled.

**Not done:** the server secrets still share the 4 KB. If a later setting
pushes it over again, the next step is moving secrets to Parameter Store
(`apps/web/lib/secrets/parameter-store.ts` already reads it).
