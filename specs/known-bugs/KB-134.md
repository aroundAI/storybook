## KB-134 — Tests that scan the whole repository run against vitest's 5-second default and fail when the machine is busy

**Severity:** Low. No product behaviour is affected. A red unit stage blocks a
pull request whose code has nothing to do with the failing test, and costs a
rerun. **Found:** 2026-09-27, #441's local CI run. `film-607-edit-suite-retired.test.ts
› no application or infrastructure file names the Edit Suite` timed out at
5.3 s during the unit stage, and passed when run alone at the same commit (1.8 s for the whole file,
startup included).

The retired-feature scans read every source file in the repository. How long
that takes depends on the size of the repository and on what else the machine
is doing: film-607 took 368 ms alone and 5.3 s under load, about 14 times as
long.

### Measured (2026-09-28, alone, quiet machine)

Every test that walks directories from the repository root, slowest test per
file:

| ms alone | File | Timeout |
|---:|---|---|
| 812 | `apps/web/test/account-budget-retired.test.ts` | added `30_000` |
| 691 | `packages/next/__tests__/kb6-caught-action-message.test.ts` (two scans) | added `30_000` |
| 526 | `packages/shared/__tests__/vendor-api-versions.test.ts` | had `60_000` |
| 368 | `apps/web/test/film-607-edit-suite-retired.test.ts` | added `30_000` |
| 264 | `apps/web/test/film-513-lip-sync-retired.test.ts` | added `30_000` |
| 172 | `apps/web/test/film-514-music-vendors-retired.test.ts` | had `30_000` |
| 204 and below | 16 more, down to 1 ms | none needed |

### Fix

A scan taking 250 ms or more alone gets the explicit `30_000` that film-514
already had: at the 14 times slowdown measured, anything from about 350 ms
up can pass 5 s. No global timeout was raised, so a test that hangs still
fails at 5 s.

### Acceptance criteria

- [x] Every directory-walking test measured alone (table above)
- [x] Each one at 250 ms or more carries an explicit timeout
