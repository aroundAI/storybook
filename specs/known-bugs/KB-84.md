## KB-84 — Every role on an account reads its vendor keys' ciphertext

> **Fixed (2026-09-25), #PRNUM.** Members lost SELECT on `encrypted_key`
> (column grants, as KB-43 did for tokens), and every key read and the
> settings save go through `packages/supabase/src/external-api-keys.ts`,
> which checks the caller on their own client before its admin read or
> upsert. **The proposed fix alone would have broken saving a key:** the
> settings save is an upsert, and ON CONFLICT DO UPDATE reads `encrypted_key`
> back through EXCLUDED (measured: `permission denied`). The entry named six
> readers; there were ten, in seven files — `packages/features/assets/src/lib/server/voice.actions.ts`
> was missing. The owner also decided (2026-09-25) that only account owners
> add, replace or remove keys: the write policies now call
> `can_manage_account_api_keys`, the helper checks the same rule, and other
> roles see which providers are connected, without the last four characters.
> That also closes a gap the entry did not name: UPDATE needs no SELECT, so
> any member could overwrite a key without reading it.

**Severity:** Low while the encryption key stays server-side; the same shape as
KB-43 for platform tokens. **Found:** KB-46 (2026-09-24); **reproduced**
against the local DB: a team member with no project role and a project viewer
each read the account's `external_api_keys` row, `encrypted_key` included.

`external_api_keys_read` is `has_account_access(account_id)`, and
`authenticated` holds SELECT on every column. Any member can fetch every
provider's encrypted key through PostgREST. The app itself reads the column
only to decrypt server-side, or to show the last four characters.

### Proposed fix

Revoke column SELECT on `encrypted_key` from `authenticated`. Read it with the
service role, after an explicit access check, in the key helpers
(`project-audio-settings.ts`, `voice-profile-actions.ts`,
`voice-clone-actions.ts`, `config-loader.ts`, `elevenlabs-connection.actions.ts`,
the settings key list). Add a pgTAP test listing the columns a member may read.

### Acceptance criteria

- [x] pgTAP: a member selecting `encrypted_key` is refused; the other columns still read — `apps/web/supabase/tests/database/external-api-key-grants.test.sql` (21 checks; 11 failed on `main` before the run stopped at the missing function)
- [x] Only account owners add, replace or remove a key, in the database and in the app — same pgTAP file; `apps/e2e/tests/account/api-keys.spec.ts`
- [x] No file but the helper and the service-key workers reads the ciphertext — `packages/supabase/__tests__/external-api-key-access.test.ts`
