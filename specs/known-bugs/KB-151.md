## KB-151 — Instagram average watch time is requested and then discarded, and the Reels skip rate is never requested

**Severity:** Low. No figure is wrong. Two figures Instagram documents for
Reels are missing, so Instagram's Attention stage shows as dark rather than
measured. No creator is misled: the signal map names this KB as the blocker.
**Found:** 2026-10-01, building the signal map (FILM-1714). Instagram
Attention binds `ig_reels_avg_watch_time` as its primary signal and
`reels_skip_rate` as supporting.

### What happens

- **`ig_reels_avg_watch_time`** has been requested for every Reel since
  FILM-1712 (`instagram-insights.ts`, `metricsForType`), and the provider
  returns it as `totals.avgWatchTimeMs`. Nothing reads it after that.
  `normalizeAnalytics` in `analytics-sync-cron.ts` builds the Instagram
  snapshot from `watchTimeMs` but not the average, and
  `buildSnapshotDeltaRow` (`ingest.ts`) pins `avg_view_duration_seconds` to
  `null` for Instagram. The value survives only inside the `raw_data`
  payload, which no reader parses. FILM-1712's evidence says "the average is
  kept as Meta reports it". Meta's value is kept only in that unparsed
  payload.
- **`reels_skip_rate`** is in the field reference
  (`docs/platform-capability-reference.md`, `instagram/media-insights`) and
  is never requested.

The `watch_time` capability family is `derived` for Instagram because the
*total* is stored, so the family level cannot show either gap.
`SIGNAL_INPUT_GAPS` in `packages/clickhouse/src/lib/signal-map.ts` records
both, and their signals read `not_ingested` with this KB as the blocker.

### Reproduced (2026-10-01)

```bash
git grep -n "avgWatchTimeMs" -- packages apps
# instagram-insights.ts:183 and instagram/types.ts:71 only: produced, never consumed
git grep -n "reels_skip_rate" -- packages/features/content-analytics/src
# nothing: never requested
```

The stale-gap test in `packages/clickhouse/__tests__/signal-map.test.ts`
("is stale once its marker appears") runs the same scan. It passes today
because neither marker is present.

### Fix

1. Carry the average through ingest without deriving it. It is **not**
   total ÷ views: Meta divides by its own count, 121 against 221 views in
   FILM-1712's check. The unit is milliseconds, confirmed 2026-09-29. Store
   it as reported, in a column that is not `avg_view_duration_seconds`,
   because YouTube's figure there is a different quotient. Then remove the
   `ig_reels_avg_watch_time` gap from `SIGNAL_INPUT_GAPS`.
2. Request `reels_skip_rate` for REELS and store it as a percentage. Then
   remove its gap.

### Acceptance criteria

- An Instagram Reel's average watch time reaches ClickHouse as Meta reports
  it, null when Meta omits it, and is never derived from the total.
- `reels_skip_rate` is requested for REELS only and stored, null when
  omitted.
- Both entries leave `SIGNAL_INPUT_GAPS`. The stale-gap test fails until
  they do.
