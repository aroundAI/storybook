## KB-141 — Publishing a video to LinkedIn through uploadVideo fails: createPost reads an id LinkedIn does not send in the body

> **Fixed (2026-10-01), #489.** `createPost` and `createTextPost` now share
> `readPostUrn`, which reads `x-restli-id` first and falls back to a body `id`.
> The `it.fails` "publishes a video through the provider end to end" in
> `linkedin-journey.test.ts` is a normal `it` now and passes; reverting the
> header read turns it (and the text-post test) red.

**Severity:** Medium. Every LinkedIn video publish that goes through
`LinkedInProvider.uploadVideo` (the immediate publish in
`packages/features/publishing/src/server/publish-actions.ts:945` and the
scheduled one in `packages/features/publishing/src/jobs/process-scheduled-publishes.ts:580`)
throws after the video is uploaded, so the user sees a failed publish although
the video reached LinkedIn. It is not High only because the SQS publish worker
posts through the ugcPosts route, which does not call `createPost`.
**Found:** 2026-09-30, building the LinkedIn sandbox journey (FILM-1802).

`createPost` (`packages/features/publishing/src/providers/linkedin/linkedin-provider.ts:248`)
posts to `/posts` and then does `const data = await response.json()` and
`if (!data.id) throw new Error('LinkedIn post creation failed: Missing post ID')`
(lines 282-288). The Posts API answers 201 with the new post's URN in the
`x-restli-id` response header and no body. `createTextPost` in the same file
already reads the header (line 122); `createPost` does not.

### Reproduced (2026-09-30)

`apps/vendor-sandbox/__tests__/linkedin-journey.test.ts:218`, the `it.fails`
test "publishes a video through the provider end to end", drives
`new LinkedInProvider(token).uploadVideo(...)` against the sandbox, which
serves the Posts API as documented (201, header, no body). The test asserts
`result.postUrn` matches `urn:li:share:` and it fails, which `it.fails` counts
as a pass:

```
pnpm --filter vendor-sandbox exec vitest run __tests__/linkedin-journey.test.ts __tests__/tiktok-journey.test.ts
 ✓ __tests__/linkedin-journey.test.ts (11 tests)
   ✓ ... > publishes a video through the provider end to end
 Test Files  2 passed (2)   Tests  21 passed (21)
```

The sandbox's own fidelity test also asserts POST /posts has no body, so
serving one to make the app pass would turn both red.

### Proposed fix

Read `x-restli-id` first in `createPost`, as `createTextPost` does, and fall
back to a body `id` only if present. Share one helper between the two.

### Acceptance criteria

- [ ] `createPost` returns the URN from `x-restli-id`
- [ ] In `linkedin-journey.test.ts` the `it.fails` "publishes a video through
      the provider end to end" is changed to `it` and passes
