## KB-129 — Canon extraction records its LLM usage under the project id, so the insert fails and the call goes unrecorded

**Severity:** Low. The story still generates and canon is still committed;
what is lost is the record of one LLM call per story. **Found:** FILM-1806,
driving a full studio run through the local job queue, 2026-09-25.

After a story is generated, the llm-worker commits it to the canon tables
and runs `canon-extraction` to find narrative threads
(`apps/web/lambda/llm-worker/utils/commit-story-canon.ts:391-394`):

```ts
context: {
  name: 'canon-extraction-auto',
  accountId: projectId,
},
```

`executeLLM` passes `context.accountId` to `recordUsage`, which inserts an
`llm_usage_analytics` row. `account_id` references `accounts`, and a project
id is not an account, so the insert fails:

```
[LLM Analytics] Failed to log usage: code 23503
insert or update on table "llm_usage_analytics" violates foreign key
constraint "llm_usage_analytics_account_id_fkey"
Key (account_id)=(<the project's id>) is not present in table "accounts".
```

`recordUsage` swallows the error (on purpose, so analytics never fails a
generation), so nothing else shows it. Every story's canon-extraction call,
with its tokens and cost, is missing from the account's usage.

The caller has the right id: `story-generation.ts` holds `data.accountId`
and does not pass it to `commitStoryCanon`. It is the only
`accountId: projectId` in the repo (`grep -rn "accountId: *projectId"`).

**Reproduced** with `apps/e2e/tests/sandbox/studio-flow-evidence.spec.ts`
against the local job queue: the error appears in `.sandbox/workers.log` at
the story stage. The id it names is in `projects` and not in `accounts`.

### Acceptance criteria

- [ ] `commitStoryCanon` takes the job's account id and passes it as
  `context.accountId`; seen red first by a test that records the
  `recordUsage` call's account id.
- [ ] After a story generation, the canon-extraction call has an
  `llm_usage_analytics` row under the team's account.
