## KB-115 — The season outliner's step always fails: it reads .episodes from the array executeLLM already unwrapped

**Severity:** Medium. Season generation still returns episodes. They just never
come from the outliner, whose output is validated against the prompt's schema;
they come from whatever the director model writes in its final answer, which
nothing validates. **Found:** FILM-1803, driving the season orchestrator
against the AI sandbox, 2026-09-25.

`season-outline.json` sets `output.wrapper_key: "episodes"` over an array, a
legitimate use (KB-107's guard allows it). `executeLLM` validates the whole
object and returns `result.data` as **the array**. The outliner skill
(`packages/features/episodes/src/agent/skills/season-outliner-skill.ts`) then
reads `result.data.episodes`, which is `undefined` on an array, and
`episodes.length` throws. The tool returns
`Season outline generation failed: Cannot read properties of undefined (reading 'length')`
on every call.

`runSeasonOrchestrator` prefers the outliner step's episodes and falls back
to `result.data.episodes` from the director's final answer, so the handler
(`apps/web/lambda/llm-worker/handlers/season-outline.ts`) still reports
success, carrying unvalidated, model-written outlines.

**Reproduced** by running `runSeasonOrchestrator` against the AI sandbox
(`apps/vendor-sandbox/__tests__/orchestrators.test.ts`, which lists it in
`KNOWN_TOOL_FAILURES` with this id and error).

It is KB-107's class: a caller reads a wrapper key the executor has already
removed. KB-107's guard checks what a `wrapper_key` names, not what callers of
that prompt read.

### Acceptance criteria

- [ ] The outliner reads the array `executeLLM` returns; the season
  orchestrator's episodes come from the validated step. Seen red first against
  the sandbox
- [ ] A guard fails on any caller that reads `.data.<wrapper_key>` of a prompt
  with a `wrapper_key`
