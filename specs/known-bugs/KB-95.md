## KB-95 — The audio library's Delete hides the card and deletes nothing

> **Fixed (2026-09-25), #385.** Delete asks for confirmation and calls
> `deleteAudioAssetAction`. The action soft-deletes the row as the caller:
> `can_write_project` first, then the update policy. After that it removes
> the file with the server's storage client, if the file is the asset's own
> and nothing uses it. "Its own" means `ownedAudioAssetLocation`: an upload
> key in the project's audio folder, or one of the three generated layouts
> built from the asset's id and project. A writer can rewrite `file_url`, so
> the URL alone never chooses what the server deletes.
>
> A file that a timeline track (by id, `metadata.audio_asset_id`, or the URL
> it copied) or a cue still uses is kept. This was a lead decision
> (2026-09-25): the episode keeps playing it. A viewer is refused with a
> returned message, and an asset still generating is refused too.
>
> The fix found two readers that ignored `deleted_at`, so a deleted asset
> was matched to new cues again: the prompt-hash match in
> `audio-cue-actions.ts`, and `match_audio_assets()`. Both now skip deleted
> rows (migration `20260925110437`). Kept and orphaned files have no sweep
> yet; that is a lead (`leads/2026-09-25-kb-95.md`).
>
> Guards: `delete-audio-asset.test.ts`, `owned-audio-asset.test.ts`,
> `cue-match-deleted.test.ts`, `audio-assets-deleted.test.sql`, and the
> E2E `storage/audio-library-delete.spec.ts` (production build). Each was
> seen red first; `tooling/mutation-guards/kb-95.json` has the mutations.

**Severity:** Low — the user is told something false; nothing is lost.
**Found:** KB-79 (2026-09-24). **Reproduced** 2026-09-24 (Playwright, dev
server): an asset seeded in a project, Delete chosen from its card menu. The
card disappears; the row's `deleted_at` stays `null`; after a reload the
card is back.

`AudioLibraryClient.handleDelete` only hides the id locally
(`apps/web/app/home/[account]/studio/[projectSlug]/audio-library/_components/audio-library-client.tsx`,
`// TODO: Call delete action`). There is no delete action for `audio_assets`.

### Proposed fix

A soft-delete action gated by `can_write_project`, which also removes an
uploaded file from its own folder (`isAudioLibraryPath`), with a
confirmation dialog; or remove the menu item until it exists.

### Acceptance criteria

- [x] After Delete and a reload, the asset is gone and its row is soft-deleted (E2E, red first)
- [x] A project viewer cannot delete
