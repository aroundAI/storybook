## KB-159 — A signed-out lifecycle action loops redirected refetches instead of reaching sign-in

> **Fixed (2026-10-01), #507.** Reproduced first, red: with the browser at
> 4× CPU and 1.5s latency, Start after the session ended left the page on
> the Change log for 14s+ while it POSTed a redirected action every 1.5s
> (2 of 2 runs). `runAction` now returns on a redirect error instead of
> toasting it and reading the change back, and the app's `QueryClient`
> never retries a query whose action redirected. Same conditions after the
> fix: sign-in in ~3.7s, no action after the Start (3 of 3).

**Severity:** Low — a user whose session ended clicks a lifecycle button
and, on a slow connection or server, stays on the page while it sends
requests, instead of reaching sign-in. Nothing is written: the action is
refused by its own auth check. **Found:** FILM-1610's H11 guard went NOT
GREEN in the 🧬 E2E guards job (run 36880685814, shard 3), 2026-10-01, and
passed on the next run.

### Cause

H11 (FILM-1610 review 5) lets a signed-out server action through the
middleware so `enhanceAction`'s `requireUser` can answer with a redirect the
client follows. It does: the CI server log shows `POST …/experiments 303`
→ `GET /auth/sign-in?_rsc 200`. But Next.js 15 rejects the action's promise
with `NEXT_REDIRECT`, and Change log's `runAction` treated that as a
refusal: it toasted it and called `refresh()` and `detailQuery.refetch()`.
Those are server actions too. Next.js runs actions one at a time in the
router's queue, ahead of the redirect's navigation, and each of them
redirected and failed in turn; react-query retried each failure (3 retries,
1s/2s/4s back-off) because the page, never left, was still observing them.
The server log shows ten such cycles in the test's 10s.

### Fix

- `experiments-client.tsx:240` — a redirect error returns from `runAction`
  before any toast or read-back.
- `apps/web/components/react-query-provider.tsx:23` — the class: no query
  in the app retries a redirected action.
