## KB-180 — next build and the Connected apps page fail because a client form imports @kit/studio-mcp, which pulls node:async_hooks into the browser bundle

> **Fixed (2026-10-03), #576.** `@kit/studio-mcp` has a client-safe
> subpath, `@kit/studio-mcp/scopes`. The Connected apps form, the consent
> form and the two Zod schemas they share import values from it.
> `packages/features/studio-mcp/__tests__/client-bundle.test.ts` fails when
> anything a `'use client'` file imports reaches the package root.

**Severity:** Medium. `pnpm --filter web build` fails, so nothing deploys,
and the Connected apps settings page (and the OAuth consent page) cannot
load under webpack dev. Turbopack dev does not show it. **Found:** FILM-1908
work (t1908), when `apps/e2e/tests/mcp/connected-apps.spec.ts` failed.

### What happens

The form `create-personal-access-token-form.tsx` (`'use client'`) imports
`MCP_SCOPES` from `@kit/studio-mcp`. The root re-exports
`request-context.ts`, which imports `AsyncLocalStorage` from
`node:async_hooks`. Webpack cannot bundle a `node:` URI for the browser:

```
Failed to compile.
node:async_hooks
Module build failed: UnhandledSchemeError: Reading from "node:async_hooks" is not handled by plugins (Unhandled scheme).
Import trace for requested module:
node:async_hooks
../../packages/features/studio-mcp/src/request-context.ts
../../packages/features/studio-mcp/src/index.ts
./app/home/[account]/settings/connected-apps/_components/create-personal-access-token-form.tsx
> Build failed because of webpack errors
```

The same chain exists through the two schema files
(`connected-apps.schema.ts`, `consent.schema.ts`), which the consent form
shares, so fixing only the form leaves `next build` failing; that was
measured.

### How it was reproduced

`main` @1b1882ad0, `pnpm --filter web build`: exit 1 with the trace above.
After the fix, `pnpm --filter web build` exits 0. The Playwright spec
`connected-apps.spec.ts` on a webpack dev server: four failed attempts with
the fix reverted, one pass with it.
