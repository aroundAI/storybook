## KB-198 — The calendar check and the breaking preview can be clicked before the channels load, and answer "still loading"

> **Fixed (2026-10-18), #674.** `ScheduleReleasePanel` takes
> `channelsLoading`, which the Publish screen sets from its channels query
> (`loadingConnections`). While it is true, Check channel calendars
> (`release-check-calendar`) and the Breaking news tab's Preview breaking
> release (`breaking-preview`) are disabled, carry `data-loading="true"` and
> `aria-busy`, and read "Loading channels…" beside a spinner; once the
> channels are read they enable. The value refusal `CHANNELS_LOADING`
> stays, as a second guard behind the button. Tests:
> `release-checks-wait-for-channels.test.tsx` (both buttons, loading then
> loaded), and the E2E 'the calendar check and the breaking preview wait
> for the project’s channels (KB-198)' in `cadence-release.spec.ts`, which
> holds the channels' server action with `page.route` and sees both buttons
> wait, then the first click answered with the calendar. The E2E specs wait
> for the buttons to be enabled instead of retrying: the `toPass` loop in
> `breaking-release.spec.ts` is gone. Guards KB198-U1..U3 and KB198-E1 in
> `tooling/mutation-guards/kb-198.json`.

**Severity:** Low. A person who clicks while the channels load is told to
check again and has to click a second time; nothing is written or sent.
It also made `cadence-release.spec.ts` fail about one run in three.

**Found:** while fixing FILM-2209 (#670), which turned the early click's
wrong error into the value refusal "The channels are still loading. Check
again in a moment."

### What happens

The Publish screen renders the Schedule Release panel at once, and reads
the project's channels afterwards with a `useQuery` around
`getConnectedPlatformsAction`. Both previews need those channels, so until
the query returns, `onPreviewCadence` and `onPreviewBreaking` answer with
`CHANNELS_LOADING`. The buttons that call them were enabled the whole
time.

Reproduced in `cadence-release.spec.ts`: the first test picks a date and
clicks Check channel calendars as soon as the panel shows, and failed
about one run in three on `release-calendar-post` never appearing, with
"The channels are still loading" on the page. `breaking-release.spec.ts`
worked around the same race by clicking the preview in a `toPass` retry
loop. Held deterministically by delaying the channels' server action with
`page.route`: without the fix the button is enabled while the read is
pending (the new E2E fails on `toBeDisabled`).

### Acceptance criteria

- [x] While the channels load, both buttons are disabled and show that
  they are loading.
- [x] Once the channels are read, both enable, and the first click is
  answered with the calendar or the preview.
- [x] The `CHANNELS_LOADING` refusal stays as a second guard.
- [x] The E2E specs wait for the buttons to be enabled, with no retry loop
  or sleep; each passes five runs in a row.
