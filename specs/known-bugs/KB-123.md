## KB-123 — An episode's video can be set to any URL, and publishing fetches it or hands it to the platform

**Severity:** Medium. Any project writer chooses the file a publish sends to the channel: another tenant's video on the same storage host, or a file on a host they control. The thumbnail had the same shape (KB-104). **Found:** KB-104 (2026-09-25), sweeping the other URL fields a publish uses.

`updatePublishedVideoAction` (`packages/features/episodes/src/lib/server/mutations/publish-actions.ts`) takes `videoUrl: z.string()` and stores it in `episodes.localized_videos` with no check. `updateShortsGroupsAction`, in the same file, stores `shorts_groups` the same way. Writers can also update `episodes` directly through the API. Every publish path then uses the stored URL:

- **Downloaded by the app:** the worker's X and LinkedIn handlers (`fetch(job.videoUrl)`), YouTube in the worker and in process (`getVideoStream`).
- **Handed to the platform to pull:** TikTok, Instagram and Facebook.

### Reproduced (2026-09-25, `b1b01d7b`)

The real `updatePublishedVideoAction`, in a throwaway vitest file in `packages/features/episodes`, with the Supabase client stubbed. I called it for episode `…e1` with a video URL under another episode's folder (`…/project-assets/episodes/…e2/videos/en-1.mp4`). The update it sent:

```json
[{"localized_videos":{"en":"https://abcdefghijklmnop.supabase.co/storage/v1/object/public/project-assets/episodes/00000000-0000-4000-8000-0000000000e2/videos/en-1.mp4"}}]
```

This has not been driven through a publish end to end, because that needs a connected channel. The path from the stored value to the download was traced by reading, as cited above.

### Why it was not fixed with KB-104

New videos are uploaded to `episodes/<id>/videos/` (`publishVideoPath`), so the KB-104 check (`ownedPublicKey` in `@kit/storage/public-url`) could require that folder. But older episodes may name videos elsewhere, for example shot videos under `projects/<P>/shots/`, or files from the retired in-app generation. A check added at publish time would stop those from publishing. Production's distribution needs counting first, by the owner, since production credentials are off limits:

```sql
select
  count(*) filter (where final_video_url is not null)                                   as final_video_urls,
  count(*) filter (where final_video_url like '%/episodes/' || id || '/videos/%')        as final_in_own_folder,
  count(*) filter (where localized_videos is not null and localized_videos <> '{}'::jsonb) as with_localized
from public.episodes;
```

### Proposed fix

1. The two save actions accept only a URL under the episode's own videos folder, as KB-90 does for thumbnails.
2. The publish paths check it again, as KB-104 does, because the column is writable.
3. Legacy values outside the folder are handled per the count: re-homed, or explicitly allowed under the same project's prefix.

### Decisions and the production count (2026-09-25)

- **The count (owner, 2026-09-27).** The query below, run on production: `1 own episode, videos folder` — 2 URLs, 1 episode. Every stored video URL is the episode's own upload; nothing sits outside the boundary, so nothing is re-homed and no publish that worked before is refused. (An earlier session's record of a count could not be traced to a query; this one replaces it.)
- **The boundary (owner):** a publish sends a file of the episode's **own project** on the app's storage: its own folders, a sibling episode's, or the project's. `episode-video-scope-storage.test.sql` shows this grants nothing new. A project member can already write each of those, and cannot write another project of the same account, which is why the boundary stops at the project.
- **Save time:** a new or changed value must be the episode's own upload (`episodes/<id>/videos/`, where every UI upload goes).
- **No database trigger (owner).** The publish-time check is the backstop for direct API writes.
- **One resolver.** The three copies that picked a video (the scheduled Lambda, the scheduled job, publish-now) are one function, `resolveEpisodeVideo`. Each caller keeps its old precedence, so this publishes exactly what it did before; a test compares it against the three old copies over 640 input combinations. The copies disagree; see the leads file.

### Acceptance criteria

- [x] A saved video URL outside the episode's own videos folder is refused (unit test, red first). A value the episode already holds is kept. `episode-video-save.test.ts` and `storage/__tests__/episode-video.test.ts`; mutation guards in `kb-123.json`.
- [x] Every publish path uses a video only when it belongs to the episode's own project: publish-now, retry, the in-app scheduled job, the scheduled Lambda, and the worker. The rule is `ownedEpisodeVideo`, tested with one case per count class on R2 (r2.dev, as production) and on Supabase. `episode-video-paths.test.ts` checks that each path calls it; a mutation guard per path.
- [x] The owner has run the count below, and there are no legacy rows to handle: 2 URLs, both class 1 (2026-09-27)

### The count (read-only; counts only, no URLs)

```sql
with urls as (
  select e.id as episode_id, e.project_id, e.final_video_url as url
    from public.episodes e
   where coalesce(e.final_video_url, '') <> ''
  union all
  select e.id, e.project_id, kv.value #>> '{}'
    from public.episodes e,
         jsonb_each(coalesce(e.localized_videos, '{}'::jsonb)) kv
   where jsonb_typeof(kv.value) = 'string'
  union all
  select e.id, e.project_id, v.value #>> '{}'
    from public.episodes e,
         jsonb_array_elements(case when jsonb_typeof(e.shorts_groups) = 'array'
                                   then e.shorts_groups else '[]'::jsonb end) g,
         jsonb_each(case when jsonb_typeof(g -> 'videos') = 'object'
                         then g -> 'videos' else '{}'::jsonb end) v
   where jsonb_typeof(v.value) = 'string'
)
select
  case
    when url like '%/episodes/' || episode_id || '/videos/%' then '1 own episode, videos folder'
    when url like '%/episodes/' || episode_id || '/%'        then '2 own episode, another folder'
    when exists (select 1 from public.episodes s
                  where s.project_id = u.project_id and s.id <> u.episode_id
                    and u.url like '%/episodes/' || s.id || '/%') then '3 another episode, same project'
    when url like '%/projects/' || project_id || '/%'        then '4 the project''s own folder'
    when url ~ '/(episodes|projects)/[0-9a-f-]{36}/'         then '5 another project''s file'
    else '6 not an app storage path'
  end as class,
  count(*) as urls,
  count(distinct episode_id) as episodes
from urls u
group by 1
order by 1;
```
