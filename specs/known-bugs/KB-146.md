## KB-146 — Two analytics chart tooltips draw with a transparent background, because they wrap colour tokens in hsl()

> **Fixed (2026-10-01), #TBD.** Every `hsl(var(--…))` in `apps/` and
> `packages/` now uses the token bare: the two tooltips, the sidebar's
> outline ring, and twelve in `apps/dev-tool`'s chart story, whose
> stylesheet holds full colours too (`var(--color-…)`). No stylesheet in
> the repo declares a token as an HSL triple. `colour-tokens-not-hsl.test.ts`
> fails on any wrap of a token that is not one, and listed all 18 on main.
> `chart-tooltip-evidence.spec.ts` hovers both tooltips in light and dark
> and reads the computed paint: on a build with the fix reverted all four
> were `rgba(0, 0, 0, 0)` with a `0px` border; now each is its token's
> colour with a 1px border. Found while checking: the comparison tooltip
> prints views as dollars, filed as KB-158.

**Severity:** Low. The Recharts tooltips on two analytics charts have no
background and no border, so the tooltip text sits directly over the chart
lines. Nothing is lost or misreported; it is hard to read. **Found:**
2026-10-01, checking every consumer of `--chart-N` while de-duplicating the
ramp (FILM-1708).

The design tokens are full colours — `oklch(…)` or `#121212`, never the bare
`H S% L%` triple shadcn's older themes used — so `hsl(var(--card))` is
`hsl(#121212)`, which is invalid CSS. The browser drops the declaration and
the property falls back to its initial value.

- `packages/features/content-analytics/src/components/analytics-enhancement-cards.tsx:126-127`
  — `backgroundColor: 'hsl(var(--card))'`, `border: '1px solid hsl(var(--border))'`
- `packages/features/content-analytics/src/components/language-trend-chart.tsx:137-138`
  — `backgroundColor: 'hsl(var(--popover))'`, `border: '1px solid hsl(var(--border))'`
- `packages/ui/src/shadcn/sidebar.tsx:551` — `hsl(var(--sidebar-border))` and
  `hsl(var(--sidebar-accent))` inside a `shadow-[…]` class, so that ring never draws.

The same shape on `--chart-1` in `revenue-chart.tsx` (the revenue line's
colour) was fixed in FILM-1708, #498, since it is a consumer of the ramp
that spec changed. `apps/dev-tool` has its own stylesheet and was not checked.

### Reproduced (2026-10-01)

In Chromium (Playwright), with `--card: #121212` and
`--chart-1: oklch(53% 0.15 250)` on `:root`:

| `background-color` set to | computed |
|---|---|
| `hsl(var(--card))` | `rgba(0, 0, 0, 0)` |
| `hsl(var(--chart-1))` | `rgba(0, 0, 0, 0)` |
| `var(--chart-1)` | `oklch(0.53 0.15 250)` |

### Proposed fix

Use the token bare — `var(--card)`, `var(--border)` — or the Tailwind
utility where a class is available. Then grep `hsl(var(--` across the repo to
leave none.
