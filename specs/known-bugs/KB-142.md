## KB-142 — Publishing a video to TikTok through uploadVideo fails: the provider reads upload_id, TikTok answers publish_id

> **Fixed (2026-10-01), #489.** `initUpload` reads `publish_id` and
> `upload_url`, `uploadVideo` returns the `publishId`, and the `video_upload_id`
> step is gone. The init is now the direct-post endpoint with `post_info`
> (privacy mapped PUBLIC/FRIENDS/SELF to TikTok's enum). The `it.fails`
> "publishes through the provider end to end" in `tiktok-journey.test.ts` is a
> normal `it` now and passes; restoring the `upload_id` read turns it red.

**Severity:** Medium. Every TikTok publish through `TikTokProvider.uploadVideo`
(`packages/features/publishing/src/server/publish-actions.ts:849`, scheduled:
`packages/features/publishing/src/jobs/process-scheduled-publishes.ts:498`)
fails at its first call, so the user gets an error and no post. Not High: the
SQS publish worker uses its own direct-post code and does not go through the
provider, and until KB-143 is fixed TikTok direct posting is refused anyway.
**Found:** 2026-09-30, building the TikTok sandbox journey (FILM-1802; FILM-702
is unverified for this reason).

The provider initialises with `/post/publish/inbox/video/init/`
(`packages/features/publishing/src/providers/tiktok/tiktok-provider.ts:170`)
and then requires `data.data.upload_id` and `data.data.upload_url`
(lines 197-203). TikTok answers `publish_id` and `upload_url`; there is no
`upload_id`, so it throws `TikTok init failed: Missing upload_id or upload_url`.
Past that, the provider sends `video_upload_id` to the direct-post init
(line 275), a field that call does not take.

### Reproduced (2026-09-30)

`apps/vendor-sandbox/__tests__/tiktok-journey.test.ts:128`, the `it.fails`
test "publishes through the provider end to end", runs
`new TikTokProvider(token).uploadVideo(...)` against the sandbox and expects a
`publishId`. It fails, so `it.fails` passes:

```
pnpm --filter vendor-sandbox exec vitest run __tests__/linkedin-journey.test.ts __tests__/tiktok-journey.test.ts
 ✓ __tests__/tiktok-journey.test.ts (10 tests)
 Test Files  2 passed (2)   Tests  21 passed (21)
```

### Proposed fix

Follow TikTok's sequence: read `publish_id` and `upload_url` from the init,
upload the chunks to `upload_url`, then poll `publish/status/fetch` with the
`publish_id`; drop the `video_upload_id` step. Which init (inbox or direct
post) the provider should use depends on KB-143.

### Acceptance criteria

- [ ] `uploadVideo` reads `publish_id` and `upload_url` and returns the
      `publishId`
- [ ] In `tiktok-journey.test.ts` the `it.fails` "publishes through the
      provider end to end" is changed to `it` and passes
