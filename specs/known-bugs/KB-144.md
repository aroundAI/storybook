## KB-144 — A published TikTok post gets no URL: the publish worker reads video_id, which TikTok does not return

**Severity:** Low. The post is created; the publish record just has an empty
URL, so the user has no link to it and anything keyed on the video id (matching
it to analytics) has nothing to match. Only reachable once KB-143 lets the
post through. **Found:** 2026-09-30, building the TikTok sandbox journey
(FILM-1802).

`uploadToTikTok` (`apps/web/lambda/publish-worker/handlers/tiktok.ts:81`) does
`const videoId = statusData.data?.video_id` on `PUBLISH_COMPLETE`, and
builds `https://www.tiktok.com/@user/video/${videoId}` only if it is set.
TikTok's status response has no `video_id`; it returns
`publicaly_available_post_id` (an array, spelled that way, present for public
posts) — see `docs/platform-capability-reference.md:995`. So `videoId` is
always `undefined` and the function returns `url: ''`. (The URL it would build
also uses the literal `@user`, not the account's handle.)

### Reproduced (2026-09-30)

`apps/vendor-sandbox/__tests__/tiktok-journey.test.ts:161-163`: after the
worker publishes against the sandbox, the log line reads `Upload complete:
undefined` and the test asserts `expect(published.url).toBe('')`. This is a
normal test pinning today's behaviour, not an `it.fails`; when the bug is
fixed it must be changed to expect a URL containing the post id, which is the
flip.

```
pnpm --filter vendor-sandbox exec vitest run __tests__/linkedin-journey.test.ts __tests__/tiktok-journey.test.ts
 stdout | ... [TikTok] Upload complete: undefined
 Test Files  2 passed (2)   Tests  21 passed (21)
```

### Proposed fix

Read `publicaly_available_post_id[0]` (string-safe: 19-digit ids lose
precision through `JSON.parse` as numbers) and build the URL from the
account's handle, or store the id and leave the URL empty when the post is not
public.

### Acceptance criteria

- [ ] The worker returns the post id from `publicaly_available_post_id`
- [ ] The assertion `expect(published.url).toBe('')` at
      `tiktok-journey.test.ts:163` is replaced by one expecting the post id in
      the URL
