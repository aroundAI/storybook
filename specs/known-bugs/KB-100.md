## KB-100 — Profile settings are unreachable in production: personal accounts are off, so /home/settings redirects, and the user menu has no link

> **Fixed (2026-09-25), #426.** Profile settings moved to a `(profile)` route
> group outside `(user)`, whose layout redirects every personal page to a
> team. The URL is still `/home/settings`, so sign-in `next=` links, the
> identity-linking redirect and existing specs keep working. The user menu has
> a **Profile settings** item on every page that shows it, including the
> create-team page, which had no menu at all.

**Severity:** High. Every signed-in person, in every deployment: nobody can
change their password or email, enrol MFA, link an identity, change their
name or avatar, or delete their account. **Found:** KB-99, while making local
runs match production (2026-09-25).

### Reproduced

On main, with `NEXT_PUBLIC_ENABLE_PERSONAL_ACCOUNTS=false` (the value
`sst.config.ts:940` deploys):

- `apps/web/app/home/(user)/layout.tsx:27-40` redirects every page under
  `(user)`, `settings` included, to `/home/<first team>` or to
  `/home/teams/create`, before the page renders.
- The user menu (`packages/features/accounts/src/components/personal-account-dropdown.tsx`)
  linked only Home, Docs and, for super-admins, Admin.
- `use-link-identity-with-provider.ts:17` returns people to `/home/settings`,
  which then bounces.
- The create-team page, where anyone without a team lands, had no user menu:
  no settings, and no way to sign out.

The E2E suite couldn't see any of this, because it ran with personal accounts
on (KB-99).

### Acceptance criteria

- [x] A team member opens **Profile settings** from the user menu, saves their
      name twice, and it survives a reload — `apps/e2e/tests/account/profile-settings.spec.ts`
- [x] Someone with no team reaches settings from the create-team page's menu
      (same spec)
- [x] `/home`, `/home/projects` and `/home/billing` still send a team member to
      their team; `/home/settings` stays put (same spec)
- [x] Screenshots in the PR: the menu, the page after the second save, and
      the create-team landing
