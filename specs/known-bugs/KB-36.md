## KB-36 — TikTok credentials saved at /admin/platforms are ignored by connect and refresh

> **Fixed (2026-09-25), #397.** Reproduced first on main (`ddc5568a`) through
> the real refresh path: with a TikTok row saved as the admin page writes it
> and no env keys, refresh returned `APP_NOT_CONFIGURED` with **0** vendor
> requests; with both set, TikTok received the **env** key. Now one rule
> holds for every app, in `getOAuthAppCredentials`
> (`packages/features/publishing/src/server/oauth-app-credentials.ts`): the
> row saved at `/admin/platforms` if the app can be saved there, otherwise
> its env pair. A saved row that cannot be read or decrypted counts as not
> configured, without falling back to env. One list,
> `SAVED_CREDENTIAL_APPS` (`src/oauth/apps.ts`), drives the admin page's
> cards, the save action's enum and the resolver, so the page cannot offer an
> app the resolver ignores. Each card now says which source is in effect:
> *Saved here*, *From environment variables*, *Saved, but cannot be read*,
> or *Not configured*. Design: `specs/plans/KB-36-edd.md`.

**Severity:** Medium — the owner's saved TikTok key was silently not the one
in use. With env unset, TikTok connect refused although the page said
"Configured"; with env set, rotating the key on the page did nothing.
**Found:** KB-29 (2026-09-23), Decision 3 of its EDD. **Fixed.**

TikTok credentials saved at `/admin/platforms` are ignored by connect and refresh.

### Before deploying (owner, production, read-only)

The saved row now wins over `TIKTOK_CLIENT_KEY`. Check whether production
has one:

```sql
select platform, client_id, updated_at from oauth_app_credentials where platform = 'tiktok';
```

- No row, or a row whose `client_id` equals the deployed `TIKTOK_CLIENT_KEY`:
  nothing changes on deploy.
- A different key: delete the row at `/admin/platforms` first to keep today's
  app, or accept one reconnect per TikTok connection (a refresh token is
  bound to the app that minted it).

### Acceptance criteria

- [x] Unit, red first: a saved TikTok row is used by refresh with no env keys (red on main: `APP_NOT_CONFIGURED`, 0 requests)
- [x] Unit, red first: the saved row wins over env (red on main: the env key was sent)
- [x] Unit, red first: an undecryptable saved row is not configured and does not fall back to env
- [x] Every app the admin page offers is configured by a saved row alone (iterates `SAVED_CREDENTIAL_APPS`)
- [x] The admin page shows the source in effect per app, with no secret (unit + E2E `admin/platform-credentials.spec.ts`)
