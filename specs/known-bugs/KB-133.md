## KB-133 — Publish Now uploads the first Shorts group of a language for every group, so a second group's short never goes out

> **Fixed (2026-09-27), #430.** `publishToAll` passes the short's
> `shortsGroupId` to `resolveEpisodeVideo`.

**Severity:** Medium. The publish screen sends one publish per Shorts group,
language and channel, naming the group. The scheduled paths (Prepare
Schedule, the cron) upload the named group's short. Publish Now did not: for
a short it took the first group holding that language, whatever the request
named. With two groups in one language, the first short went out twice and
the second never did. The owner's intended behaviour is that every short is
published (2026-09-27). **Found:** re-checking KB-123's publish-path lead
against that description.

### Reproduced (2026-09-27, KB-123's branch)

`packages/features/publishing/__tests__/publish-now-shorts-group.test.ts`: an
episode with two English groups, `group-a` then `group-b`. A Publish Now of a
short naming `group-b` uploaded `group-a`'s file (red); naming `group-a`
passed only because it is first.

### Fix

`publishToAll` passes the short's `shortsGroupId` to `resolveEpisodeVideo`,
which already filters by it for the scheduled paths. A full-video publish is
unchanged.

### Acceptance criteria

- [x] A Publish Now of a short uploads the named group's video (unit, red first): `publish-now-shorts-group.test.ts`; guard P1 in `tooling/mutation-guards/kb-133.json`
