📖 Story Generation

Turning a chosen idea into a full narrative with characters, arcs, and the SCORE framework for episode continuity.

After you pick your favorite idea, the app writes the whole story — like a bedtime story but for a video. It knows how long the video should be (1 minute? 5 minutes? 2 hours?) and writes just the right amount. It also remembers what happened in past episodes so it doesn't tell the same story twice!

Input Schema

The story generation stage receives a rich input object from the ideation stage's chosen idea, combined with episode metadata and optional user overrides:

// StoryGenerationInput schema
{
  episodeId: string;
  version: number;              // Optimistic locking
  title: string;                // 1-255 chars
  logline: string;              // 10-500 chars
  targetDuration: number;       // 60-7200 seconds
  contentStyle?: 'dialogue-heavy' | 'action-heavy' | 'balanced';
  themes?: string[];
  hook?: string;
  visualDirection?: string;
  characters?: { name: string; description: string }[];
  worldDetails?: string;
  style?: string;
  threadCandidates?: { threadId: string; threadName: string; action: 'progress' | 'resolve' }[];
}
💡 Optimistic Locking

The version field prevents concurrent edits from clobbering each other. The server rejects mutations where the submitted version doesn't match the stored version, forcing a refresh before retry.

The 5-Layer Story Prompt

The story generation prompt is the most sophisticated in the pipeline. It uses five distinct layers to transform a short logline into a full, production-ready narrative:

Layer 1 — Role Definition

Sets the AI persona as an expert storyteller and narrative designer for visual media. This framing primes the model for structured, cinematic storytelling rather than generic prose.

Layer 2 — Story Craft

Encodes proven screenwriting techniques directly into the prompt:

  • Opening hooks: 95% of viewers leave within 3 seconds — the story must open with something visually or emotionally arresting.
  • 3-act pacing: Classic structure (setup → confrontation → resolution) with duration-aware scene counts.
  • Scene-level curiosity gaps: Each scene must end with something that compels the viewer to watch the next.

Layer 3 — Viral Engineering

Carries forward the viral framework from Ideation, but applied at the narrative level:

🎯
Curiosity Gaps

Not just at the concept level — now embedded in the narrative structure. Every scene boundary creates a micro-gap that keeps viewers watching.

❤️
Emotional Anchors

The story must ground its themes in universal feelings — not abstract morals, but visceral emotions that make viewers care enough to share.

Layer 4 — Change Authorization

The most unique layer. It enforces narrative integrity by requiring every character change to pass three tests:

🔗
Caused

The change must be caused by prior events in the story. No deus ex machina.

💰
Costly

The change must cost the character something — comfort, safety, a relationship. Free growth isn't growth.

🔀
Constraining

The change must alter future constraints. If a character learns something, it must close some doors and open others.

Layer 5 — Output Format

Constrains the model to emit valid JSON matching the StoryData schema. Like Ideation, this uses generateObject() from the Vercel AI SDK for guaranteed schema compliance.

The SCORE Framework

Every generated story produces SCORE metadata — a compact summary that enables episode continuity across a series. This is what prevents the AI from telling the same story twice.

🏆
SCORE — Series Continuity & Orchestration Record
Injected into future episode prompts as memory context
Field Type Purpose
episodeSummary string 2–3 sentence plot summary — what happened, who was involved, how it ended. Enough for the AI to avoid repeating this plot.
sentimentScore number (0–1) Emotional tone of the episode. 0 = dark/tense, 0.5 = balanced, 1 = joyful/light. Used to vary emotional arcs across a season.
keyEvents string[] Major plot points that affect future episodes — character revelations, relationship shifts, world-state changes.
💡 Why SCORE Matters

Without SCORE, an AI generating episode 10 has no memory of episodes 1–9. It would accidentally repeat plots, forget character growth, and create continuity errors. SCORE acts as compressed episodic memory — giving the model just enough context to maintain series coherence without overwhelming the context window.

Duration-Based Scaling

Content requirements scale automatically based on the target duration. The calculateContentScaling() function determines how much story to generate:

Duration Words Scenes Dialogue Lines Shots
1 min ~150 2 ~8 ~9
5 min ~750 ~7 ~41 ~43
30 min ~4,500 ~45 ~248 ~257
2 hrs ~18,000 ~180 ~660 ~1,028

The scaling isn't linear — it follows a curve calibrated against real screenwriting data. A 5-minute episode isn't 5× a 1-minute episode; it has proportionally more dialogue and fewer rapid cuts. The contentStyle parameter further adjusts the ratio:

  • dialogue-heavy: More dialogue lines, longer scenes, fewer shots per scene
  • action-heavy: Fewer dialogue lines, shorter scenes, more shots (rapid visual cuts)
  • balanced: Default middle-ground calibration
import { calculateContentScaling } from '@kit/episodes';

const scaling = calculateContentScaling({
  targetDurationSeconds: 300,    // 5 minutes
  contentStyle: 'dialogue-heavy', // or 'balanced', 'action-heavy'
});
// Returns: ~750 words, ~7 scenes, ~40 dialogue lines, ~43 shots

Canon Context Injection

Before the LLM is called, the system builds a rich context payload from the project's canon database. This is what makes the AI "know" the show's world.

The context injection pipeline loads and formats four categories of data:

1. buildCanonContext()

The primary loader function. It queries the project's metadata tables and assembles:

  • Character Registry: Full character profiles — names, roles, physical descriptions, personality traits, relationships
  • Location Registry: All available settings with descriptions and visual details
  • Recurring Elements: Signature moments (e.g., "The Clue Board") with placement rules
  • Visual Style: The project's aesthetic direction (e.g., "3D Pixar/DreamWorks cartoon")

2. formatRecurringElementsForPrompt()

Transforms recurring element data into prompt-ready text with placement annotations:

// Raw database row
{ name: "The Clue Board", placement: "throughout", description: "..." }

// Formatted for prompt
"- The Clue Board (placement: throughout): Dante pins clues to a corkboard,
   connecting them with colored string as the mystery unfolds."

3. Previous Episode Titles

Loaded from the episodes table with their SCORE summaries. Injected as a numbered list so the AI can see what stories have already been told and avoid repetition.

4. Memory Context (Canon Memory)

The most sophisticated injection. Loads three types of persistent narrative state:

  • Immutable events: Things that happened and can't be undone (e.g., "Dante's treehouse was upgraded in Ep 3")
  • Active threads: Ongoing plot lines the user selected as threadCandidates to progress or resolve
  • Character states: Current emotional/relational state of characters based on accumulated episode history

Output Structure

The LLM produces a structured StoryData object that feeds directly into the Screenplay Conversion stage:

interface StoryData {
  title?: string;
  logline?: string;
  fullStory?: string;
  actBreakdown?: { act1: string; act2: string; act3: string };
  characters?: StoryCharacterArc[];
  themes?: string[];
  tone?: string;
  estimatedSceneCount?: number;
  targetDuration?: number;
  contentStyle?: ContentStyle;
  episodeSummary?: string;       // SCORE: plot summary
  sentimentScore?: number;       // SCORE: 0-1 emotional tone
  keyEvents?: string[];           // SCORE: major plot points
}

Key design decisions in the output structure:

  • fullStory is the prose narrative — a readable story that the user can review and edit before passing to screenplay.
  • actBreakdown provides explicit 3-act structure summaries, making it easy for the Screenplay stage to map scenes to acts.
  • characters tracks character arcs — who changed and how — feeding back into Canon Memory for future episodes.
  • SCORE fields (episodeSummary, sentimentScore, keyEvents) are generated alongside the story and stored for series continuity.

Thread Candidates

Before generating a story, users can select existing narrative threads from Canon to weave into the episode. This gives the creator direct control over series-level plot progression.

▶️
Progress a Thread
action: 'progress'

Advance an ongoing plot line — reveal a new clue, deepen a mystery, or escalate the stakes. The thread remains active for future episodes.

✅
Resolve a Thread
action: 'resolve'

Bring a plot line to its conclusion — answer the question, complete the arc, pay off the setup. The thread is marked complete in Canon after generation.

For "Little Detective Dante", the user might select:

"threadCandidates": [
  {
    "threadId": "thread_missing_locket",
    "threadName": "The Missing Locket Mystery",
    "action": "progress"
  },
  {
    "threadId": "thread_luna_art_show",
    "threadName": "Luna's Big Art Show",
    "action": "resolve"
  }
]

The AI will weave these threads into the story — dropping another locket clue and bringing Luna's art show to a satisfying conclusion.

LLM Configuration

🤖
Model Configuration
Optimized for narrative generation
Parameter Value Rationale
Model gemini-3-flash-preview Balances creativity with coherence — story generation needs more capability than ideation but not full-precision models
Temperature 0.65 Slightly lower than ideation (0.8) — we want creative prose but with consistent narrative structure and character voices
Max Tokens 16000 Generous budget for full stories — a 30-minute episode can produce ~4,500 words of narrative plus act breakdowns and SCORE metadata
Output Mode generateObject() Guarantees valid JSON output matching the StoryData Zod schema — no parsing needed

Compared to ideation's gemini-3.1-flash-lite, the story stage uses a more capable model because it must produce coherent, long-form prose with consistent character voices, thematic depth, and precise act structure — tasks where lighter models tend to lose coherence.
