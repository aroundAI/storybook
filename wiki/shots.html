📸 Shot Generation (Visual Studio)

Scene-by-scene VEO 3.1 prompt generation with 7-component structure, timeline events, reference images, and shorts/reel scoring.

Now we have a movie script. But a camera operator needs to know: How close should the camera be? Should it pan left? What's in the background? The Shot Generator creates detailed instructions for each camera shot — like a recipe for an AI video generator (VEO 3.1) to create the actual video clips.

The Scene-by-Scene Pipeline

Shot generation doesn't process the entire screenplay at once. Instead, it uses a scene-by-scene pipeline that builds context once, then processes each scene independently — yielding massive token savings.

Step 1 — Build Global Context

Called once per generation run. The function buildGlobalShotContext() queries the project's character and location registries, building a comprehensive context object that includes:

👥
Character Registry
15+ physical attributes per character

Age, ethnicity, hair color & style, eye color, build, clothing, accessories, distinguishing features. This ensures every shot prompt describes characters with exact visual consistency.

📍
Location Registry
Visual descriptions for every setting

Interior/exterior flags, lighting conditions, key props, color palette, mood descriptors. Used to generate the Scene component of VEO 3.1 prompts.

Step 2 — Process Each Scene

For each scene in the screenplay, filterContextForScene() extracts only the characters and locations that appear in that scene. This filtered context is sent to the LLM alongside the scene's dialogue and action lines, producing a list of shots tailored to that scene.

Because each scene only receives its own slice of context — not the entire project registry — token usage drops by 50–80% compared to a monolithic approach.

Step 3 — Aggregate & Persist

aggregateSceneResults() takes all per-scene shot arrays and assigns globally sequential shot numbers (e.g., Scene 1 shots 1–6, Scene 2 shots 7–12). Then batchCreateShotsAction() writes them to the shots table in a single batch insert.

The 7-Component VEO 3.1 Prompt

Every shot produces a structured prompt with seven distinct components. This structure was optimized through iterative testing against VEO 3.1's rendering engine to maximize visual fidelity and minimize artifacts.

Component Description Example
Subject 15+ character attributes "DANTE (7, curly black hair, brown eyes, red detective coat)"
Action Movements, micro-expressions "Peers through magnifying glass, eyes widen"
Scene Environment, props, lighting "Cozy treehouse lab, cork boards, warm sunlight"
Style Camera shot, angle, movement "Medium close-up, eye-level, slight dolly-in"
Dialogue Colon syntax prevents subtitles "Dante: 'The footprints are backwards!' (Tone: excited)"
Sounds Ambient + effects "Birdsong, magnifying glass clinking"
Negative Exclusion instructions "No subtitles, no captions, no watermarks"
💡 Why Colon Syntax for Dialogue?

VEO 3.1 interprets quoted text as subtitles to burn into the video. Using Name: 'text' (colon syntax) instead of "text" tells VEO to generate the speech audio without rendering on-screen text. This single formatting trick eliminates one of the most common VEO artifacts.

A complete VEO 3.1 prompt for a single shot might look like:

// Assembled VEO 3.1 prompt
"DANTE (7, curly black hair, brown eyes, olive skin,
slim build, red detective coat, magnifying glass)
peers through magnifying glass at muddy footprints,
eyes widen with excitement, slight gasp.
Cozy treehouse lab interior, cork boards covered
in pinned clues, warm golden sunlight through window.
Medium close-up, eye-level, slight dolly-in.
Dante: 'The footprints are backwards!' (Tone: excited discovery)
Birdsong outside, magnifying glass clinking on wood.
No subtitles, no captions, no watermarks, no text overlay."

The 9-Layer System Prompt

The shot generation system prompt is the most complex in the entire pipeline — a 9-layer architecture that gives the LLM comprehensive directorial authority.

Layer 1 — Role

Sets the persona: "You are a VEO 3.1 Director specializing in AI-generated video production." Establishes expertise in both filmmaking craft and AI video model behavior.

Layer 2 — Cinematic Authority

Grants lens specificity (24mm–100mm range) and establishes the principle that camera = emotion. Wide shots (24mm) for establishing mood, tight close-ups (85mm+) for emotional beats. The LLM must justify camera choices based on narrative intent.

Layer 3 — Scene Shorts / Reel Scoring

Each scene receives a sceneViralScore (1–10) evaluating its potential as a standalone short or reel. High-scoring scenes get flagged as shortsCandidate: true with metadata for platform-specific formatting.

Layer 4 — Format

Enforces timestamp format [00:00–03:00] for each shot, with a hard max 8 seconds per shot. This constraint aligns with VEO 3.1's optimal generation window — longer shots degrade in quality.

Layer 5 — Context / Reference Images

Instructs the LLM to reference images by name, not describe them. If a character has a reference image uploaded, the prompt says "See: dante_ref.png" rather than re-describing the character. VEO 3.1 can accept image references directly.

Layer 6 — Audio Cues

Specifies SFX, music, and ambient sound per shot. Separating audio into its own layer prevents audio hallucinations — VEO 3.1 sometimes generates phantom sounds if audio isn't explicitly declared.

Layer 7 — Transition Intelligence

Defines transition types between shots:

continuation
Same scene, next beat
cut
Hard scene break
match_cut
Visual rhyme
j_cut
Audio leads video
l_cut
Video leads audio

Layer 8 — Frame Descriptions

Each shot includes firstFrameDescription and lastFrameDescription — prose descriptions of the opening and closing frames. These serve as visual anchors for VEO 3.1, improving temporal consistency within the generated clip.

Layer 9 — Location Specificity

Goes beyond generic location names. Each shot specifies locationArea (e.g., "treehouse lab — window nook") plus a prose description of that specific area. This prevents VEO from rendering generic versions of named locations.

Timeline Events

Each shot contains an array of timeline events — micro-level actions happening within the shot's time window. These events drive the audio studio's dialogue placement and the visual studio's animation timing.

// TimelineEvent interface
interface TimelineEvent {
  startTime: string;    // '00:00'
  endTime: string;      // '03:00'
  type: 'action' | 'dialogue' | 'transition' | 'reaction';
  character?: string;
  content: string;
  emotion?: string;
}

A single shot might contain multiple overlapping events:

{ "timelineEvents": [ { "startTime": "00:00", "endTime": "02:00", "type": "action", "character": "Dante", "content": "Leans in close to examine muddy footprints", "emotion": "focused" }, { "startTime": "02:00", "endTime": "04:00", "type": "dialogue", "character": "Dante", "content": "The footprints are backwards!", "emotion": "excited discovery" }, { "startTime": "04:00", "endTime": "05:00", "type": "reaction", "character": "Luna", "content": "Gasps and looks at Dante with wide eyes", "emotion": "surprised" } ] }
🎬
action
Physical movements & gestures

Character performs a visible action — walking, examining, pointing. Drives VEO's motion generation.

💬
dialogue
Spoken lines with emotion tags

Maps directly to TTS generation in the Audio Studio. The emotion field controls voice inflection.

🔄
transition
Scene or beat changes

Marks where one narrative beat ends and another begins within a single shot. Used for editing decisions.

😲
reaction
Facial expressions & responses

Secondary character reactions — gasps, smiles, nods. Critical for multi-character scenes where the camera isn't on the speaker.

⚡ 50–80% Token Savings vs Monolithic

The monolithic approach sends the entire screenplay + all characters + all locations in a single LLM call. For a 7-scene episode with 12 characters and 8 locations, that's ~15,000 tokens of context repeated for every shot.

The scene-by-scene pipeline sends only the 2–3 characters and 1–2 locations relevant to each scene. A typical scene uses ~3,000 tokens of context — an 80% reduction. Over an entire episode, this compounds into massive cost savings without sacrificing output quality.

Compared to other pipeline stages, shot generation uses a lower temperature (0.4 vs 0.8 for ideation) because camera directions need to be technically precise — there's less room for creative latitude in lens choices and timing than in story concepts. The higher token budget (16000 vs 8000) accommodates the verbose 7-component prompt structure multiplied across multiple shots per scene.
