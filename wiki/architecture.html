🏗️ System Architecture

The complete monorepo structure, package relationships, multi-tenant architecture, and how all pieces work together.

The Storybook app is like a big LEGO castle. It's made of many smaller LEGO boxes (packages) that each do one thing really well. There's a box for stories, one for billing, one for emails, one for the database, and they all click together!

Monorepo Structure

The entire platform lives in a single Turborepo monorepo. Every app, package, and tooling config is versioned together — a single pnpm install and pnpm dev boots the whole system.

💡 Why a Monorepo?

Atomic commits across packages, shared TypeScript config, single CI pipeline, and Turborepo's remote caching make this the right call for a platform with 20+ interdependent packages.

Multi-Tenant Architecture

Storybook supports two account types. Every row in the database is scoped to an account via foreign keys — this is the foundation for Row Level Security (RLS).

👤
Personal Accounts
auth.users.id = accounts.id

Created automatically when a user signs up. The account ID is the user's auth ID — a 1:1 mapping. Personal accounts own projects, episodes, and billing subscriptions directly.

👥
Team Accounts
Shared workspaces with members

Created explicitly by a user. Team accounts have a memberships table linking users → teams with roles: owner, admin, or member. All data within the team is shared.

⛔ RLS Is Non-Negotiable

Every table with user data uses Supabase Row Level Security. Policies check auth.uid() against the ownership chain: User → Account → Project → Episode → Shots. If you skip RLS, any authenticated user can read any data.

Key Design Decisions

Major architectural choices and why they were made:

📦
Turborepo Monorepo
Build system

Parallel builds, shared TypeScript configs, and Turborepo's remote caching give near-instant CI for unchanged packages. One pnpm dev boots the entire system.

⚡
Server Actions over API Routes
Data mutations

Type-safe end-to-end with Zod validation. Collocated with the UI that calls them. No manual fetch() boilerplate. Built-in CSRF protection from Next.js.

🗃️
JSONB over Normalized Tables
story_data, screenplay_data

Story structures evolve faster than SQL schemas. Using JSONB columns for story_data and screenplay_data means new fields ship without migrations. Zod validates the shape in code.

🔌
Provider Abstraction
@kit/providers-* packages

Every external service (DB, storage, email, queue, cache) is wrapped in an abstract interface. Switch from Supabase Storage to S3 by changing one env var — zero code changes.

📝
JSON Prompt Templates
Editable without deploys

LLM prompts live in .json files with variable placeholders. Product teams can tweak prompt wording, scoring rubrics, and constraints without touching TypeScript or triggering a deploy.

🏗️
SST for Infrastructure
sst.config.ts

All AWS resources (Lambda, SQS, S3, CloudFront, WebSocket API) defined in a single TypeScript file. Type-safe infrastructure that deploys with npx sst deploy.

Technology Choices

The full technology stack, from framework to infrastructure:

Layer Technology Why
Framework Next.js 15 (App Router) Server Components, Server Actions, streaming, RSC — the full modern React stack
Language TypeScript (strict) End-to-end type safety from database types to React props
Styling Tailwind CSS 4 + Shadcn UI Utility-first CSS with pre-built accessible components. Design system consistency.
Database Supabase PostgreSQL Managed Postgres with built-in RLS, real-time subscriptions, and connection pooling
Auth Supabase Auth OAuth, MFA, magic links — all built-in. JWT tokens integrate with RLS policies.
Hosting AWS Lambda via SST Pay-per-invocation, auto-scaling, OpenNext adapter for full Next.js compatibility
AI Vercel AI SDK + Gemini Unified interface for multiple LLM providers. generateObject() for structured output.
Monorepo Turborepo + pnpm Parallel task execution, remote caching, workspace protocol for internal packages
Queue AWS SQS Serverless message queue. ~$1/month for typical usage. Decouples AI tasks from request lifecycle.
Cache Upstash Redis Serverless Redis with HTTP API. 10K commands/day free tier. Used for rate limiting and session data.
Email Resend React Email templates + Resend delivery. 3K emails/month free. Scales to SES for production.
Testing Vitest + Playwright Vitest for unit/integration (fast, Vite-native). Playwright for E2E browser tests.
