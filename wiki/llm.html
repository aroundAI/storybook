🤖 LLM Integration

Provider abstraction, model configurations, structured output, and the generateObject pattern.

The app talks to AI brains (Gemini, ChatGPT, Claude). Instead of being locked to one, it can switch like changing TV channels. The LLM layer is a universal remote.

Provider Abstraction

The @kit/llm package wraps the Vercel AI SDK, providing a unified interface to multiple LLM providers. A factory-pattern singleton ensures only one client instance exists per process.

💎
Gemini (Primary)
Google DeepMind

Default provider. Models: gemini-2.5-flash, gemini-3.1-flash-lite. Best cost/quality ratio for structured output and creative generation.

🔵
OpenAI
GPT-4o / GPT-4o-mini

Fallback provider. Strong at instruction-following and JSON mode. Used when Gemini quotas are exceeded or for specific task types.

🟠
Anthropic
Claude 3.5 Sonnet

Tertiary provider. Excels at nuanced creative writing and long-context tasks. Higher cost but superior narrative quality.

🐋
DeepSeek
DeepSeek-V3

Budget option for high-volume, low-complexity tasks. Competitive with GPT-4o-mini at a fraction of the cost.

Switching Providers

Provider switching requires zero code changes — just update the environment variable:

// .env
LLM_PROVIDER="gemini"        // or "openai", "anthropic", "deepseek"

// Each provider needs its own API key
GOOGLE_GENERATIVE_AI_API_KEY="AIza..."
OPENAI_API_KEY="sk-..."
ANTHROPIC_API_KEY="sk-ant-..."
DEEPSEEK_API_KEY="dsk-..."

Factory Pattern Singleton

The LLM client is created once and reused across all server actions. This prevents connection churn and ensures consistent configuration:

// packages/llm/src/llm-client-factory.ts (simplified)
let cachedClient: LLMClient | null = null;

export function getLLMClient(): LLMClient {
  if (cachedClient) return cachedClient;

  const provider = process.env.LLM_PROVIDER ?? "gemini";
  cachedClient = createClient(provider);
  return cachedClient;
}

Model Configuration per Template

Different pipeline stages require different creativity vs. precision tradeoffs. Each prompt template specifies its own model configuration in its JSON definition:

🎨
Creative

Temperature: 0.8

Used for: Ideation, story brainstorming. Maximizes diversity and surprise in outputs.

⚖️
Balanced

Temperature: 0.65–0.7

Used for: Story generation, screenplay. Balances creative expression with structural adherence.

🎯
Precise

Temperature: 0.4–0.6

Used for: Shot generation, VEO prompts. Strict format compliance and deterministic output.

The configuration lives inside each prompt template's JSON file under the modelConfig key:

// prompts/story-generation/ideation.json (excerpt)
{
  "modelConfig": {
    "model": "gemini-3.1-flash-lite",
    "temperature": 0.8,
    "maxTokens": 8000
  }
}

Structured Output

Every LLM call in the pipeline uses generateObject() from the Vercel AI SDK. This guarantees the response matches a Zod schema — no manual JSON parsing, no regex extraction, no prayer.

The generateObject() Pattern

import { generateObject } from 'ai';
import { z } from 'zod';

const IdeaSchema = z.object({
  ideas: z.array(z.object({
    title:          z.string(),
    logline:        z.string(),
    themes:         z.array(z.string()),
    hook:           z.string(),
    visualPotential: z.string(),
    viralPotential: z.object({
      score:          z.number().min(1).max(10),
      curiosityGap:   z.string(),
      emotionalAnchor: z.string(),
      shareability:   z.string(),
    }),
  })),
});

const result = await generateObject({
  model:       getLLMClient(),
  schema:      IdeaSchema,
  system:      systemPrompt,
  prompt:      userPrompt,
  temperature: 0.8,
});

Fallback: extractJSON()

Some models (especially older or smaller ones) occasionally wrap JSON in markdown fences, <think> blocks, or produce truncated output. The extractJSON() utility handles these edge cases:

🛡️ What extractJSON() Handles
  • Markdown fences: Strips ```json ... ``` wrappers
  • Think blocks: Removes <think>...</think> preambles
  • Truncated JSON: Attempts bracket-matching repair for cut-off responses
  • Leading text: Scans for the first { or [ character
// packages/llm/src/extract-json.ts (simplified)
export function extractJSON<T>(raw: string): T {
  let cleaned = raw
    .replace(/```json\n?/g, '')
    .replace(/```\n?/g, '')
    .replace(/<think>[\s\S]*?<\/think>/g, '')
    .trim();

  const start = cleaned.search(/[{\[]/);
  if (start > 0) cleaned = cleaned.slice(start);

  return JSON.parse(cleaned);
}

Cost Tracking

Every LLM call is logged to the llm_usage table for cost monitoring, debugging, and quota management.

Column Type Description
id uuid Primary key
account_id uuid FK to accounts — for per-team billing
episode_id uuid FK to episodes — associates cost with content
provider text gemini, openai, anthropic, deepseek
model text Exact model string (e.g., gemini-2.5-flash)
prompt_tokens integer Input token count
completion_tokens integer Output token count
total_cost_usd numeric Calculated cost based on provider pricing
pipeline_stage text ideation, story, screenplay, shots, etc.
created_at timestamptz When the call was made
💰 Cost Estimation Example

A full 5-minute episode through the complete pipeline (Ideation → Story → Screenplay → Shots → Audio) costs roughly $0.03–$0.08 with Gemini Flash models. The llm_usage table enables per-episode cost breakdowns visible in the admin dashboard.

Error Handling

LLM calls are inherently unreliable — rate limits, network timeouts, malformed responses. The platform uses a three-layer defense strategy:

🔄
Exponential Backoff

Each retry waits exponentially longer: 1s → 2s → 4s. Random jitter (±500ms) prevents all clients from retrying simultaneously.

3️⃣
3 Max Retries

Hard cap at 3 attempts. Covers transient failures (rate limits, network blips) without burning budget on permanently broken requests.

📬
Dead Letter Queue

After 3 failures, the request goes to a DLQ (SQS) with the full payload. Admins can inspect, fix, and replay from the dashboard.

⛔ Errors That Skip Retries
  • Schema validation failure: If generateObject() returns data that doesn't match the Zod schema, this is a prompt issue — retrying won't help.
  • Authentication errors (401/403): Bad API key. Fails immediately, logs alert.
  • Content policy violations: Provider refused the request. Logged for review, not retried.
