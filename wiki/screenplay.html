🎬 Screenplay Conversion

Transforming prose stories into professional screenplays with scenes, dialogue, ElevenLabs audio tags, and viral dialogue engineering.

The story is like a book — but to make a video, you need to know WHERE each part happens, who SAYS what, and what SOUNDS you hear. The screenplay stage turns the story into a movie script with scene headings, character dialogue, and even instructions for sound effects!

What Goes In

The screenplay stage takes a completed story and converts it into a structured screenplay format. The input is minimal because all the creative content already exists in the story.

Explicit Input

// ScreenplayInput schema
{
  episodeId: string;            // The episode to convert
  targetSceneCount?: number;    // 2–200, optional override
  dialogueStyle?: 'natural' | 'stylized' | 'minimal';
  contentStyle?: 'dialogue-heavy' | 'action-heavy' | 'balanced';
}
✅ Validation Gate

Before the LLM call fires, the system checks two hard prerequisites:

  • The episode must be in story status (ideation and story stages completed)
  • The story_data.fullStory field must exist and contain the prose narrative

If either check fails, the action returns an error immediately — no tokens wasted.

The 5-Layer Screenplay Prompt

Unlike ideation's 3-layer prompt, the screenplay stage uses a more complex 5-layer architecture to handle the additional demands of dialogue engineering, audio design, and format compliance.

Layer 1 — Role Definition

Sets the AI persona as an expert screenwriter for short-form video:

"You are an expert screenwriter specializing in short-form video
content. You transform prose narratives into professional screenplays
with cinematic scene headings, natural dialogue with emotional
delivery cues, and detailed audio design."

The screenwriter persona ensures the model thinks in terms of scenes, cuts, and visual storytelling — not prose paragraphs.

Layer 2 — ElevenLabs Audio Tags

This layer defines the emotional delivery tags that get embedded directly into dialogue text. These tags are consumed by ElevenLabs TTS downstream to control how lines are spoken:

😆
[excited]

High energy, wide-eyed delivery. Used for discoveries and eureka moments.

😰
[nervous]

Shaky, uncertain tone. Used for tension and suspense beats.

😮‍💨
[sigh]

Exhale before speaking. Conveys resignation, relief, or frustration.

😂
[laughs]

Laughter mid-dialogue. Breaks tension and signals joy or disbelief.

⏸️
[pauses]

Deliberate beat of silence. Creates dramatic weight before a revelation.

🤫
[whispering]

Low, secretive tone. Used for shared secrets and conspiratorial moments.

Example dialogue with embedded tags:

DANTE: [excited] Look at this! [laughs] The footprints are backwards!
LUNA:  [curious] Backwards? [pauses] That means they weren't leaving...
DANTE: [whispering] They were coming IN. Someone was inside the whole time.

Layer 3 — Viral Dialogue Rules

Six rules that transform generic dialogue into scroll-stopping exchanges. Each rule targets a specific engagement mechanism:

🎭
SUBTEXT
Never say feelings directly

Characters show emotions through actions and word choice — never state them. "I'm scared" becomes "[nervous] Did you hear that? Maybe we should... [pauses] never mind."

💥
PUNCHLINE PLACEMENT
Best line always last

The most impactful, memorable, or funny line in any dialogue exchange is positioned as the final line. This is where attention peaks — make it count.

⚔️
CONFLICT IN EVERY EXCHANGE
Tension drives engagement

Every dialogue exchange must have characters who want different things. Agreement is boring. Even allies disagree on how to solve the problem.

❓
SCENE-END QUESTION
Hook into the next scene

Every scene ends with an unanswered question — the hookOut field. This creates a micro-cliffhanger that compels the viewer to keep watching.

💎
MICRO-REVELATION
One reveal per scene

Each scene must contain at least one small revelation — a new clue, a character's hidden motive, or an unexpected connection. This is the emotionalPeak.

✂️
DIALOGUE ECONOMY
Maximum impact, minimum words

Every word must earn its place. Cut filler, pleasantries, and exposition dumps. If a line doesn't advance plot, reveal character, or create tension — it's deleted.

Layer 4 — Audio Cue Design

Each scene includes audio cues that feed directly into the Audio Studio for generation. Three types of cues are supported:

Type Duration Characteristics Example
sfx 0.1–30s One-shot sound events, non-loopable "Magnifying glass clinking on wooden table"
ambient 10–30s Loopable background layers "Quiet treehouse with wind rustling leaves and distant birds"
music 30–300s Scored with BPM + key signature "Playful investigation theme, 120 BPM, C major, pizzicato strings"

Layer 5 — JSON Output Format

The final layer constrains the LLM to produce a strict JSON schema. Like ideation, this uses generateObject() from the Vercel AI SDK for guaranteed schema compliance.

📐 Scene Heading Format

Scene headings follow the industry-standard format: INT./EXT. LOCATION - TIME OF DAY. The AI generates these from the story's narrative, mapping prose descriptions to the project's registered locations. If a story mentions "the treehouse," it becomes INT. DANTE'S TREEHOUSE LAB.

Dialogue Timeline Extraction

After the screenplay is generated, a second pass extracts each dialogue line into the dialogue_lines table with precise timing information. This enables the Audio Studio to generate TTS audio that aligns perfectly with the visual timeline.

⏱️ Timing Algorithm

Each dialogue line is assigned a timeline_start_seconds based on a simple but effective formula:

// Dialogue timing calculation
const WORDS_PER_SECOND = 2.5;    // Average speaking rate
const GAP_SECONDS = 0.5;         // Pause between lines

for (const line of scene.dialogue) {
  const wordCount = line.text
    .replace(/\[.*?\]/g, '')   // Strip audio tags
    .split(/\s+/).length;

  const duration = wordCount / WORDS_PER_SECOND;
  line.timeline_start = currentTime;
  line.timeline_end = currentTime + duration;

  currentTime += duration + GAP_SECONDS;
}

Audio tags like [laughs] and [pauses] are stripped from the word count — they affect TTS delivery, not duration calculation. The 0.5s gap provides natural breathing room between speakers.

dialogue_lines Table Schema

Column Type Description
id uuid Primary key
episode_id uuid FK → episodes
scene_number integer Which scene this line belongs to
character_name text Character speaking (e.g., "DANTE")
character_asset_id uuid FK → project_characters, used for voice assignment
dialogue_text text Full text with ElevenLabs audio tags
timeline_start_seconds float When this line starts in the scene timeline
timeline_end_seconds float When this line ends
sequence_order integer Global ordering across all scenes
🔗 Character Linking

The character_asset_id is resolved by matching the dialogue's character field against the project's character registry (project_characters table). This link is critical — it connects each line to a specific voice profile in ElevenLabs for TTS generation in the Audio Studio.

Per-Scene Viral Fields

Each scene contains two fields specifically designed to maximize viewer retention — the emotionalPeak and the hookOut. Together, they ensure every scene has a reason to keep watching.

🔥
emotionalPeak
The scene's climactic moment

A one-sentence description of the most emotionally charged moment in the scene. This is the beat where the viewer feels something — surprise, joy, fear, or wonder.

Example: "Dante realizes the footprints are backwards — someone entered, not left"

The emotional peak is used by the Visual Studio to identify which moment deserves the most cinematic camera work and by the Audio Studio to time music swells.

🪝
hookOut
The unanswered question

An unanswered question that creates a micro-cliffhanger at the scene boundary. This is the mechanism that prevents viewers from scrolling away between scenes.

Example: "Who taught them that trick?"

The hookOut is rendered as the last visual beat of a scene — often as a close-up on a character's face processing the question. It bridges directly into the next scene's opening.

⛔ Both Fields Are Mandatory

Scenes without an emotionalPeak or hookOut are flagged as incomplete. The Zod schema enforces these as required strings — the LLM cannot skip them. This is non-negotiable: flat scenes with no peak and no hook produce content that loses viewers.

LLM Configuration

🤖
Model Configuration
Optimized for structured screenplay output
Parameter Value Rationale
Model gemini-3-flash-preview Balances creativity with format compliance — screenplays need both natural dialogue and strict JSON structure
Temperature 0.6 Moderate creativity — lower than ideation (0.8) because the story content is fixed; we need creative expression not creative invention
Max Tokens 16000 Double the ideation budget — screenplays with 5–15 scenes, dialogue, and audio cues require significantly more output tokens
Output Mode generateObject() Guarantees valid JSON output matching the Zod schema — no parsing needed

The screenplay stage uses a more capable model than ideation (gemini-3-flash-preview vs gemini-3.1-flash-lite) because it must juggle multiple complex requirements simultaneously: natural dialogue, audio tag placement, format compliance, and viral dialogue rules. The lower temperature (0.6 vs 0.8) reflects that the creative direction is already set — the model should be expressive, not inventive.
