👤 User Flows & UI

User journey from login to publishing. Studio pages, navigation, and UI decisions.

Using the app is like going on a guided adventure. First you sign up, then you create a project (like naming your show), then you add episodes. For each episode, you go through 5 rooms (Ideation → Story → Screenplay → Visual Studio → Audio Studio) and each room helps you build the next piece.

User Journey

The complete user journey from first visit to published content follows a linear progression with branching at the team/personal account level:

🔐
Authentication
Supabase Auth

Users sign up via email/password or OAuth (Google, GitHub). Supabase Auth handles session management, JWT issuance, and MFA. After signup, a personal account is automatically created with matching auth.users.id = accounts.id.

👥
Account Selection
Personal vs Team

After login, users land on the account selector. They choose their personal account or a team workspace. The selected account determines the URL namespace: /home/(user)/ for personal, /home/[account]/ for teams.

Studio Pages

Each episode's content is created through five studio pages, accessible via a tabbed interface. The route structure follows a consistent pattern:

// Studio route pattern
/home/[account]/studio/[projectId]/episodes/[episodeId]/
  ├── /ideation         // 💡 Concept generation
  ├── /story            // 📖 Full narrative authoring
  ├── /screenplay       // 🎬 Scene-by-scene screenplay
  ├── /visual-studio    // 📸 Shot list & VEO 3.1 prompts
  └── /audio-studio     // 🔊 TTS, music & SFX timeline
Page Input Output AI Model
Ideation Premise (1 sentence) 3–5 scored story concepts gemini-3.1-flash-lite
Story Selected concept Full narrative with 3-act structure gemini-2.5-flash
Screenplay Narrative text Scene list with dialogue & directions gemini-2.5-flash
Visual Studio Scenes + characters Shot list with VEO 3.1 prompts gemini-2.5-flash
Audio Studio Dialogue lines + scenes TTS audio, music, SFX timeline ElevenLabs

Navigation

The studio uses a tab-based navigation bar that persists across all five stages. Each tab shows the stage name, an icon, and a status indicator:

✅
Completed Stage
Green checkmark badge

When a stage has been completed (e.g., the user has selected an idea in Ideation), the tab shows a green checkmark. Users can navigate back to completed stages to review or edit content.

🔄
In-Progress Stage
Pulsing dot indicator

The currently active stage shows a pulsing blue dot. If an AI generation is in progress, the dot animates with a spinning loader to indicate work is happening.

🔒
Locked Stage
Greyed out, not clickable

Stages that can't be accessed yet (because their prerequisite stage isn't complete) appear greyed out with a lock icon. You can't generate a screenplay until you have a story.

⚠️
Error State
Red warning badge

If a generation fails (API error, timeout), the tab shows a red warning badge. Users can click to review the error and retry the generation.

💡 Tab Persistence

The active tab state is persisted in the URL (via Next.js App Router routes), not in local state. This means refreshing the page or sharing the URL preserves the exact studio position. Deep links like /episodes/abc/screenplay work directly.

Real-time Feedback

AI generation is asynchronous — some stages take 5–30 seconds. The UI provides continuous feedback so users never wonder "is it working?":

📡
WebSocket Notifications
Instant completion alerts

When a generation job completes, the server pushes a WebSocket message to all connected clients viewing that episode. The UI instantly transitions from "generating" to "complete" without polling. See Real-time & WebSocket for the full architecture.

⏳
Loading States
Skeleton UI + progress indicators

While generating, the UI shows skeleton loaders shaped like the expected output (cards for ideation, text blocks for story, scene cards for screenplay). A progress bar estimates completion based on average generation times for each stage.

Multi-tenant Architecture

The platform supports two account types, each with different capabilities and isolation boundaries:

👤
Personal Accounts
Individual creators

Every user gets a personal account automatically on signup. This account is for solo creators who don't need collaboration. Projects and episodes are private to the user. Route: /home/(user)/.

👥
Team Accounts
Collaborative workspaces

Team accounts are shared workspaces where multiple members collaborate on projects. Members have roles (owner, admin, member) that control permissions. Route: /home/[account]/.

Data Isolation

All data is scoped to accounts via foreign keys. Row Level Security (RLS) policies in Supabase ensure users can only access data belonging to accounts they're members of:

-- RLS policy example: projects table
CREATE POLICY "Users can view projects in their accounts"
ON public.projects
FOR SELECT
USING (
  account_id IN (
    SELECT account_id FROM public.accounts_memberships
    WHERE user_id = auth.uid()
  )
  OR
  account_id = auth.uid()  -- personal account
);
💡 Shared Projects

When a team member creates a project, it belongs to the team account — not the individual. If the creator leaves the team, the project remains accessible to all other team members. This prevents data loss when team composition changes.
